# 강의자료 집필 규정

이 문서는 이 리포의 모든 강의자료(슬라이드·노트북·실습·문서)에 적용되는 규정이다.
자료를 새로 만들거나 수정할 때 이 규정을 먼저 적용하고, 완성 후 §7 체크리스트로 검수한다.

---

## 1. 이론과 실습의 분리

| 매체 | 역할 | 담지 않는 것 |
|---|---|---|
| 이론 덱 (`lectures/*/slides.md`) | 개념·키워드의 논리적 전개. 정의와 원리 | 코드 설명, 구체 수치·실험 디테일(→발표 위임) |
| 실습 (`labs/`, 노트북) | 구현과 실행. 코드가 주인 | 이론의 재서술 |
| 논문 발표 | 구체 수치·실험·검증 | — |

- **노트북은 실습 자료다.** 이론 강의를 노트북으로 대체하거나, 노트북 마크다운 셀에서 이론을 다시 전개하지 않는다.
- 실습에서 개념이 필요하면 정의를 **한 줄로 재인용**하고 해당 덱을 참조 표시한다. 계보·동기·서사는 덱의 몫이다.
- 이론 덱에는 코드 블록을 넣지 않는다. 필요하면 개념 그림·표·의사구조로 대체하고 구현은 실습으로 위임한다.

## 2. 문체 — 모든 매체 공통

**문어체 평서문으로 쓴다.** 강의자료는 교재이지 발화 대본이 아니다.

금지 목록:

| 금지 | 예 |
|---|---|
| 청유형 | "~하자", "~해 보자", "나란히 본다", "따라가 보자" |
| 질문형 전환·수사의문문 | "그럼 생각을 빼고 행동만 시키면?" |
| 은유·서사적 수사 | 심장, 씨앗, 주인공, 반쪽, 물건, 두뇌·척추·손 |
| 구어적 표현 | "그냥", "아예", "원래 그런", "~하는 셈이다", "던지면", "그랬더니" |
| 대시(—) 연결 남용 | 문장을 대시로 이어 붙이는 전개. 논리 접속어로 잇는다 |
| 감탄·영탄 | "!", "정연하게 틀린다" 류의 경구체 |

- 비유가 직관에 필요하면 쓸 수 있으나, 반드시 **표준 학술용어와 정확한 메커니즘으로 받는다.** 비유로 끝나는 문단은 미완성이다.
- **강조 규칙:** 볼드는 정의되는 용어의 최초 등장 1회만. 한 문단에 볼드 2개를 넘기지 않는다. 이탤릭 강조는 쓰지 않는다.
- **개수를 제목·라벨에 박지 않는다.** "네 단계 계보", "세 가지 원리" 금지. 항목 수는 표·목록에서 자연히 드러난다. 순서·계보는 화살표(A → B → C)로 보인다.

## 3. 개념 전개 — 정의 우선

핵심 개념의 전개 순서는 고정이다:

**정의 → 관계·논리 → 예시 → 한계·연결**

- 첫 등장 용어는 그 자리에서 정의한다: `**용어(English term)** = 한 문장 정의` (Wei et al., 2022 형식의 출처 병기).
- 정의 없이 용어부터 쓰지 않는다. 뒤 주차에서 정의할 용어(예: 하네스→W9)는 앞 주차에서 결론 용어로 앞세우지 않는다.
- **예시는 생략하지 않는다.** 특히 형식이 핵심인 개념(CoT 프롬프트, 함수 호출 스키마 등)은 실제 예시 한 조각을 반드시 보인다. 정의만 있고 예시가 없으면 미적용으로 간주한다.
- 대학원 수준의 학술적 정확성을 유지한다. 수식 유도는 발표로 넘기더라도 표준 용어와 원리는 강의에서 정확히 짚는다.

## 4. 슬라이드 규정

- **제목은 명사구.** 서술형(-한다/-이다)·질문형(-인가/-왜)·구어·비유 제목 금지. 부제가 필요하면 "개념명 — 짧은 명사구".
- 발화 예시·진행 지시·타이밍은 HTML 주석(`<!-- -->`)에만 둔다. 본문에는 넣지 않는다. 주석 안은 대본이므로 구어 허용.
- 오늘의 지도(분 단위 배분표)와 마무리 연결 슬라이드는 유지한다.
- 한 주의 핵심 개념은 3–4개. 슬라이드·장치를 늘리기 전에 분량을 먼저 줄인다.

## 5. 노트북·코드 규정

**분량과 구성.** 실습 노트북은 실습 시간(80분)을 채우는 완결된 랩이다. 함수 하나 구현하고 끝나는 통과 의례가 아니라 다음 단계를 갖춘다:

준비 → 현상 관찰(왜 이 구현이 필요한가를 실행으로 재현) → 구현·검증 → 자동화·테스트 → **측정 가능한 개선 과제**(수치를 정의하고 프롬프트·코드를 다듬어 수치를 올리는 과제 1개 이상) → 연습문제(예측→실행→확인 형식) → 완료 기준

**참고자료 조사 의무.** 실습을 설계하기 전에 `materials/repos/`에서 해당 주제의 기존 실습·과제를 조사하고 차용한다 — 특히 DeepLearning.AI/Andrew Ng(프롬프트 작성 중심 과제, 학습목표→빌드→테스트 구조), HF agents-course(현상 재현 실험), anthropic-cookbook(패턴 레시피). 차용한 출처는 노트북 헤더에 명기한다.

**셀 구조.** 한 단위는 다음 3셀 패턴을 따른다:

1. 마크다운 — 이 셀이 무엇을 확인하는지 2–4문장(§2 문체 적용, 정의는 한 줄 재인용+덱 참조)
2. 코드 — 실행 대상
3. 마크다운 — 결과 해석 1–3문장 (해석이 자명하면 생략 가능)

**코드는 교재 품질로 쓴다.**

- 주석은 코드가 보여주지 못하는 제약·의도만 서술한다. 서사·비유·예고("오늘은 X가 주인공") 금지.
- 트릭 금지: mutable default 인자로 상태 유지(`def f(_step=[0])`), 문자열 매칭 분기에 박힌 매직 상수 등. 학생이 따라 쓸 코드다.
- 상수는 이름을 붙여 셀 상단에 모은다.
- 모의 장치(폴백·스텁)는 최소화한다. 쓸 경우 실제 경로와 파일·함수 수준에서 분리하고, 모의임을 첫 줄 주석으로 명시한다.
- docstring은 한 줄 평서문: 입력 → 출력.

## 7. 검수 체크리스트

자료 완성 후 다음을 확인한다:

- [ ] 이론 덱에 코드 블록이 없고, 노트북에 이론 재서술이 없다 (§1)
- [ ] 청유형·질문형 전환·은유·구어 표현이 본문에 없다 (§2)
- [ ] 볼드가 용어 최초 정의에만 쓰였다 (§2)
- [ ] 제목·라벨에 개수 나열이 없다 (§2)
- [ ] 모든 핵심 용어가 첫 등장에서 `**용어(English)** = ...`로 정의된다 (§3)
- [ ] 형식이 핵심인 개념마다 실제 예시가 붙어 있다 (§3)
- [ ] 슬라이드 제목이 전부 명사구다 (§4)
- [ ] 노트북 코드에 서사 주석·트릭·이름 없는 매직 상수가 없다 (§5)
