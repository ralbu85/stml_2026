# Act-only — 행동만의 생성

직접 질의와 CoT는 W2에서 다뤘다. 계보의 다음 후보는 행동만 생성하는 방식이다.

**Act-only** = 추론 생성 없이 행동만 생성하는 방식. ReAct 논문의 대조 조건이다.

```
Act 1: Search[관련 단어]
Act 2: Search[또 다른 검색]
Act 3: Finish[???]   ← 검색의 목적과 진행 상태가 유지되지 않음
```

- 검색은 수행하나, 의도와 진행 상태를 언어로 유지하지 못한다.
- 여러 단계가 필요한 문제에서 경로를 잃으며, 직접 질의보다 나쁜 경우도 보고된다.

CoT는 외부 사실 접근이 없고, Act-only는 상태 추적이 없다. 두 결함은 상보적이다.

<p class="small">Act-only의 구체 수치는 발표 ①(ReAct)에서 확인한다</p>

# ReAct — 추론과 행동의 교차

**ReAct** = 한 루프 안에서 추론(Reason)과 행동(Act)을 번갈아 수행하는 방식 (Yao et al., 2022). 매 턴은 다음 요소로 구성된다.

```
Thought      지금까지 확인된 사실의 정리 + 다음 행동의 결정
Action       도구 호출 선언   Search[...]
Observation  도구가 반환한 사실  ← 모델이 아니라 제어 루프(우리 코드)가 채움
   └────────── 답이 확정될 때까지 반복
```

- Observation을 모델이 생성하지 않는다는 점이 구조의 핵심이다. 모델은 Thought와 Action까지 생성하고, 제어 루프가 도구를 실행해 Observation을 채워 되먹인다.
- Action의 실행부가 바로 W3에서 만든 도구 레지스트리다. ReAct는 그 단발 왕복을 while 문으로 감은 것이다.
- 미세조정 없이 프롬프트만으로 작동하며, 오늘날 에이전트 루프의 원형이다. W1에서 정의한 루프가 이 구조다.

# ReAct 트레이스 — 논문 Figure 1

> **Q.** Apple Remote가 원래 제어하도록 설계된 프로그램을, Apple Remote 외에 무엇으로 제어할 수 있는가?

```
Thought 1: Apple Remote가 제어하도록 설계된 프로그램을 먼저 확인해야 한다.
Action 1:  Search[Apple Remote]
Observ. 1: … Front Row 미디어 센터를 제어하도록 설계됨 …

Thought 2: 다음으로 Front Row를 제어하는 다른 수단을 검색해야 한다.
Action 2:  Search[Front Row]
Observ. 2: 'Front Row'를 찾을 수 없음. 유사: [Front Row (software), …]
```

여기까지 질문이 두 단계 탐색으로 분해되었고, 필요한 사실이 외부에서 조달되었다. 검색 실패라는 관찰도 다음 추론의 입력이 된다.

# 작동 원리 — 조준·접지·경로 수정

```
Thought 3: 소프트웨어이므로 Front Row (software)를 검색해야 한다.
Action 3:  Search[Front Row (software)]
Observ. 3: … Apple Remote 또는 키보드 기능 키로 제어 …
Thought 4: 답은 키보드 기능 키다.  →  Finish[keyboard function keys] ✓
```

- 추론이 행동을 조준한다. 무엇을 검색할지 Thought가 결정한다.
- **접지(grounding)** = 추론을 외부에서 확인된 사실에 결속하는 것. Observation이 추론을 접지하여 환각을 차단한다.
- 실패 관찰이 경로를 수정한다. '찾을 수 없음'이라는 관찰이 다음 검색어를 결정한다 (step 2 → step 3).

교차는 CoT의 환각과 Act-only의 경로 상실을 상호 보완한다.

# 현장 노트 — 트레이스 리딩

**트레이스(trace)** = 루프의 전체 실행 기록. Thought·Action·Observation의 시퀀스이며, 에이전트 디버깅의 일차 자료다.

트레이스 리딩의 기본 절차:

1. 최종 답이 아니라 첫 오류 지점을 찾는다 — 어느 스텝에서 경로가 틀어졌는가
2. 오류의 종류를 구분한다 — 잘못된 조준(Thought) / 잘못된 호출(Action) / 오염된 관찰(Observation)
3. 해당 지점의 입력(그 시점까지의 messages)을 재현해 수정을 검증한다

운영 장치:

- **max_steps(루프 가드)** = 무한 반복을 차단하는 스텝 상한
- Final Answer 파싱 — 종료 신호의 형식을 강제하고 파싱 실패를 형식 오류 관찰로 되먹인다
- **미니 evalset** = 고정 질문 5문항의 상시 채점표. 오늘부터 매주 실습에 포함하며, 변경이 성능을 올렸는지를 느낌이 아니라 표로 확인한다 (W13에서 정식 하네스로 확장)

# ReAct의 한계

- 내부 지식만으로 충분한 과제에서는 검색이 잡음이 된다. CoT가 ReAct를 능가하는 과제가 실제로 보고된다.
- 따라서 실무의 기본형은 CoT와 ReAct의 결합이며, 무엇을 언제 결합하는지가 설계 문제다.

남는 한계는 이후 주차의 주제다:

| 한계 | 주차 |
|---|---|
| 아는 것이 없음 — 파라메트릭 지식뿐 | W5–6 RAG |
| greedy 진행 — 한 단계씩 나아가며 역추적하지 못함 | W7 계획·탐색 |
| 오답도 검증 없이 제출 | W8 자기반성 |

<p class="small">과제별 성패 수치(HotpotQA·Fever·ALFWorld)는 오늘 발표 ①(ReAct)의 Table에서 확인한다</p>

# 추론 모델 시대의 루프 설계

W2에서 추론 모델을 사용 관점으로 다뤘다. 추론 모델은 루프 설계를 바꾼다.

- 일반 모델의 루프: 여러 바퀴를 돌며 관찰로 보정한다 — 바퀴당 생각은 짧게
- 추론 모델의 루프: 적은 바퀴, 한 수를 깊게 — thinking budget이 스텝 수를 대체하는 방향
- 선택 기준은 비용이다. 생각 토큰과 루프 반복은 모두 과금되며, 어느 쪽이 저렴한지는 과제별 측정의 문제다 (→ W13)

오늘 발표 ②(DeepSeek-R1)를 위한 최소 개념:

- **강화학습(RL)** = 정답 시연 없이 보상(점수)만으로 행동 규칙을 개선하는 학습. 지도학습이 시연의 모방이라면, RL은 보상을 높이는 방향의 탐색이다.
- R1은 정답 일치·형식 준수라는 규칙 보상만으로 긴 추론과 자기 교정이 창발했음을 보고한 공개 모델이다. 훈련 세부(GRPO 등)는 발표의 선택 심화다.

# 오늘 발표와의 연결
