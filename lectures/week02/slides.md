# W1 복습 — 래퍼 다음의 문제

W1에서 에이전트를 "LLM이 다음 행동을 결정하는 시스템"으로 정의하고, `chat()` 래퍼로 모델을 연결하였다.

연결된 모델의 성능은 고정값이 아니다. 같은 모델·같은 질문이라도 프롬프트 구성에 따라 정답률이 크게 갈린다.

# 대화 구조와 few-shot

---

# messages — 대화의 실제 형태

**messages** = LLM API가 받는 입력 형식으로, 역할(role)이 붙은 메시지의 목록이다. W1에서 원시 HTTP 호출로 확인한 그 구조다.

```
[ {"role": "system",    "content": "너는 단계적으로 추론하는 조수다."},
  {"role": "user",      "content": "질문 ..."},
  {"role": "assistant", "content": "답변 ..."},
  {"role": "user",      "content": "후속 질문 ..."} ]
```

- **system** = 행동 규칙·정체성의 지정. 대화 내내 유지되는 상위 지시
- **user / assistant** = 사용자 발화와 모델 응답의 교대 기록
- 모델은 상태를 저장하지 않는다. 매 호출마다 목록 전체가 다시 전송되며, 대화의 기억이란 이 목록의 누적이다

목록 전체가 매번 재전송된다는 사실이 뒤 주차의 전제다 — 목록이 길어질수록 비용이 늘고(W9 컨텍스트), 세션이 끝나면 사라진다(W10 메모리).

# few-shot — 예시에 의한 지정

**few-shot(in-context learning)** = 원하는 입출력의 예시 몇 개를 프롬프트에 포함해, 모델이 형식과 절차를 따라 하게 만드는 기법. 가중치 갱신이 없는 학습 아닌 학습이다.

```
[예시 1]  입력: 회의는 3시부터 5시     출력: {"start": 15, "end": 17}
[예시 2]  입력: 오전 9시 반 시작       출력: {"start": 9.5, "end": null}

[질문]    입력: 점심 먹고 1시에 모임   출력:            ← 모델이 형식을 따라 생성
```

- 지시문으로 길게 설명하는 것보다 예시 두세 개가 형식을 더 정확히 지정하는 경우가 많다
- 예시는 형식만이 아니라 절차도 지정한다 — 이 성질이 바로 다음 주제(CoT)의 메커니즘이다

# 추론의 유도

---

# 직접 질의 — 기준선

**직접 질의(direct prompting)** = 풀이 과정 없이 답만 요구하는 질의 방식. 오늘의 기준선이다.

직접 질의에서 두 결함이 관찰된다.

- LLM은 다음 토큰 예측기이며 산술 회로를 갖지 않는다. 자릿수가 커지면 정답과 형태만 유사한 오답을 생성한다.
- **환각(hallucination)** = 사실이 아닌 내용을 그럴듯하게 생성하는 현상. 모델은 모르는 사실에 대해서도 답을 생성한다.

계산 한계와 환각은 결함이라기보다 다음 토큰 예측이라는 계산 구조의 귀결이며, 오늘 이후의 모든 수단은 이를 구조로 보완하려는 시도다.

# CoT — 추론 과정의 외부화

**Chain-of-Thought (CoT)** = 풀이 과정이 담긴 예시를 프롬프트에 함께 제시해, 모델이 답 이전에 추론 과정을 생성하도록 유도하는 기법 (Wei et al., 2022). few-shot의 예시에 풀이 과정을 넣은 특수형이다.

```
[예시]  Q: 로저는 공이 5개. 3개들이 캔 2개를 더 샀다. 몇 개?
        A: 5 + 2×3 = 11.  정답: 11          ← 풀이 과정을 시범으로 제시

[질문]  Q: 사과 23개에서 20개를 쓰고 6개를 더 샀다. 몇 개?
        A: 23 − 20 = 3,  3 + 6 = 9.  정답: 9   ← 모델이 과정을 따라 생성
```

성능이 오르는 원리:

- 트랜스포머는 토큰 하나를 생성할 때 고정된 수의 층을 한 번 통과한다. 토큰당 순차 계산량이 상수로 고정되어 있다.
- CoT는 풀이를 여러 토큰에 나누어 생성하게 하므로, 순차 계산 단계가 생성 토큰 수에 비례해 늘어난다. 중간 토큰이 계산의 작업 공간으로 기능한다.
- **창발(emergence)** = 작은 규모에서 없던 능력이 일정 규모 이상에서 나타나는 현상. CoT의 효과는 창발적이다. 작은 모델에서는 무효하거나 오히려 유해하다.

<p class="small">구체적 향상 폭(GSM8K 등)과 규모별 곡선은 오늘 발표(CoT)에서 확인한다</p>

# CoT의 약점 — 내부 지식 의존

```
Q: 2024년 노벨 물리학상 수상자의 소속 대학은?
Thought: 아마 ○○○일 것이다. 그는 △△대 소속이므로 답은 △△대.
         └ 추론의 구조는 정합하나 전제가 모두 허구
```

- CoT의 추론은 파라미터에 저장된 내부(파라메트릭) 지식에만 의존한다. 외부 사실을 확인하는 경로가 없다.
- 전제가 환각이면 결론도 오류다. 추론 구조의 정합성이 사실성을 보장하지 않는다.

두 가지 해결 방향이 이후 주차의 뼈대다.

- 추론 도중 외부 세계를 확인하는 단계의 삽입 → 도구(W3)와 에이전트 루프(W4)
- 추론량 자체의 확대 → 오늘 후반(test-time compute)

# 계산의 확대 — test-time compute

---

# 출력의 비결정성

LLM의 출력은 결정적이지 않다. 같은 질문에도 실행마다 다른 답이 나올 수 있다.

- LLM은 확률 분포에서 토큰을 **표집(sampling)** 한다 — 매 실행이 서로 다른 추론 경로를 따른다
- temperature = 표집의 무작위성을 조절하는 파라미터. 0이면 최빈 토큰만, 높일수록 다양한 경로
- 따라서 한 번의 응답은 여러 가능한 경로 중 하나를 뽑은 표본에 불과하다

오답을 뽑았다는 것은, 다시 뽑으면 정답이 나올 수도 있다는 뜻이다. 이 관찰이 다음 기법의 출발점이다.

# Self-Consistency — 다중 샘플 다수결

**Self-Consistency** = 같은 질문을 여러 번 샘플링해 나온 최종 답들의 다수결을 취하는 기법 (Wang et al., 2022). 지난주 교수 시연이 이 논문이다.

구하려는 것은 답 $a$의 확률이다. 답은 중간 추론 경로 $r$를 거쳐 나오므로, 특정 경로 하나가 아니라 가능한 모든 경로를 합산해야 답의 실제 확률이 된다:

$$P(a \mid q) \;=\; \sum_{r} P(a \mid r, q)\,P(r \mid q)$$

- 한 번만 물으면: 확률이 가장 높은 경로 하나가 내놓은 답만 본다 — 그 경로가 틀리면 그대로 오답
- 여러 번 샘플해 다수결: 위 합을 샘플로 근사한 것 — 서로 다른 경로가 같은 답에 모이면 그 답이 이긴다

유리한 이유: 정답은 서로 다른 경로가 같은 결론으로 수렴하는 반면, 오답은 경로마다 제각각이어서 표가 분산된다. 따라서 합산(다수결)이 정답을 부각시킨다.

# 일반화 — test-time compute

**test-time compute** = 학습(가중치)은 그대로 두고, 추론 시점에 계산을 더 써서 성능을 올리는 접근. self-consistency는 그 한 예이며, 방법군 전체는:

| 방법 | 계산을 더 쓰는 방식 |
|---|---|
| Self-consistency | 병렬로 N번 → 다수결 |
| Best-of-N | N번 생성 → **검증기(verifier)** 가 최고 선택 |
| 더 긴 사고 | 한 경로를 깊게 (다음 슬라이드의 추론 모델) |
| 트리 탐색 | 분기·평가·백트래킹 (→ W7 계획과 탐색) |

공통 원리: 학습은 그대로, 추론에서 계산 ↑ = 정확도 ↑ — 이를 **추론 시점 스케일링(inference-time scaling)** 이라 한다. (다수결과 달리 Best-of-N·트리 탐색은 답의 우열을 채점하는 검증기를 따로 요구한다.)

다만 이 계산은 무상이 아니다 — N회 반복은 비용·지연도 N배다. 실무의 질문은 "N을 몇으로 둘 것인가"가 아니라 "어떤 질문에만 N>1을 적용할 것인가"이다 (→ W6 적응형 검색에서 같은 논리 재등장).

# 추론 모델 — 사용 관점

**추론 모델(reasoning model)** = 답 이전에 긴 내부 사고(thinking)를 생성하도록 학습된 모델 (o1·DeepSeek-R1 계열). test-time compute를 모델 안에 내재화한 결과다.

**thinking budget** = 생각 토큰의 상한을 지정하는 파라미터. 벤더마다 이름은 다르나(reasoning effort 등) 개념은 하나로, 생각량은 조절 가능한 자원이다. 생각 토큰도 과금된다.

| | 일반 모델 | 추론 모델 |
|---|---|---|
| 강점 | 도구 호출·정형 작업 | 수학·계획·까다로운 판단 |
| 비용·지연 | 낮음 | 높음 (생각 토큰만큼) |

- 기본값은 저비용 일반 모델이며, 추론 모델은 병목 지점에만 투입한다
- 측정 없는 모델 선택은 배제한다 — 근거는 측정이다 (→ W13 평가)
- 추론 능력이 어떻게 학습되는가(STaR의 부트스트랩, R1의 강화학습)는 W4 발표와 선택읽기로 다룬다

# 실습 — CoT·self-consistency 실험

오후 실습에서 두 기법을 직접 만들어 비교한다 (`labs/docqa/reasoning.py`).

- CoT 프롬프트를 작성하고 직접 질의와 정확도를 비교한다
- 같은 질문을 N번 샘플링해 다수결하는 `self_consistency()`를 구현한다 (`majority_vote`)
- 완료 기준: 애매한 질문에서 N=1보다 N=5의 정확도가 높고, 그 대가로 비용이 N배임을 함께 기록한다

진행 순서: `pytest tests/test_week02.py` → `demos/week02_selfconsistency.py`

# 요약

- **messages·few-shot** — 대화는 역할 붙은 목록의 재전송이며, 예시가 형식과 절차를 지정한다.
- **CoT** — 추론 과정을 토큰으로 외부화하여 성능을 올린다. 다만 내부 지식에만 의존하므로 환각 위에 추론이 쌓인다.
- **test-time compute** — 학습은 그대로, 추론 시점의 계산으로 정확도를 산다. 추론 모델은 그 내재화이며, 생각량은 예산이다.
