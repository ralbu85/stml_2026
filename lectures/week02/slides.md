# 지난주 만든 두뇌의 민낯

지난주 만든 `llm.py`의 `chat()`에 같은 질문을 **세 번** 던지면:

```
Q: 서로 다른 두 주사위의 눈의 합이 8일 확률은?
1회차: 5/36     ✓
2회차: 7/36     ✗
3회차: 5/36     ✓
```

- LLM은 **확률적 샘플러** — 매번 다른 추론 경로를 탄다
- 한 번 물어서 나온 답 = 여러 경로 중 **하나를 뽑은 것**일 뿐
- CoT는 공짜로 3배를 줬다 (17.9→56.9). **더 밀어붙일 방법은?**

# 5–15′ · Test-time Compute
### 추론 시점에 계산을 더 쓴다

# 아이디어: 여러 번 생각시키고, 다수결

**Self-Consistency** (Wang et al., 2022)

```
                ┌→ 경로 A: … 답 5/36
질문 ─(온도>0)──┼→ 경로 B: … 답 7/36     →  다수결: 5/36 ✓
                └→ 경로 C: … 답 5/36
```

1. 같은 CoT 프롬프트로 **N개 경로를 샘플링** (temperature > 0)
2. 각 경로의 **최종 답만** 모아 다수결
3. 끝. 학습 없음, 새 프롬프트도 없음 — **돈으로 정확도를 산다**

<p class="small">GSM8K +17.9%p (PaLM 540B 기준) — 출처: Self-Consistency 논문 초록</p>

---

# 왜 되는가 (직관)

- **정답으로 가는 길은 여러 갈래지만, 도착지는 하나다**
- 오답은 제각각 다른 곳에 흩어진다 (계산 실수는 매번 다르게 틀림)
- 그래서 투표하면: 정답에 표가 **모이고**, 오답 표는 **갈라진다**

지난주 ReAct 논문에서 이미 검증된 수치를 봤다:

| HotpotQA (EM) | |
|---|---|
| CoT (1회) | 29.4 |
| **CoT-SC (21회 다수결)** | **33.4** |

# 한계와 일반화

**한계 — 다수결이 가능하려면:**
- 답이 **짧고 비교 가능**해야 (숫자·선택지 ○ / 에세이·코드 ✗)
- 오답이 흩어져야 — 모델이 **일관되게 같은 오답**을 내면 투표도 소용없다

**일반화 — test-time compute 스케일링:**

| 방법 | 계산을 더 쓰는 방식 |
|---|---|
| Self-consistency | 병렬로 N번 → 투표 |
| Best-of-N | N번 → 채점기가 최고 선택 |
| 더 긴 생각 | 한 경로를 깊게 (오늘 뒷부분의 o1/R1) |
| 트리 탐색 | 경로를 분기·평가·백트래킹 → **W4** |

**공통 원리: 학습은 그대로, 추론에서 계산↑ = 정확도↑**

---

# 공짜는 아니다 — 비용 축

- 21번 샘플 = **API 비용 21배, 지연 21배**
- 수확 체감: 처음 몇 표가 크게 올리고, 갈수록 완만 (로그형 곡선)
- 그래서 실무 질문은 **"N을 몇으로?"** 가 아니라 **"어떤 질문에 N>1을?"**
  - 쉬운 질문 → 1번 / 애매한 질문 → 다수결 (질문별 라우팅 — **W7 Adaptive-RAG 복선**)

> 오늘 실습에서 N=1 vs N=5를 **직접 비용까지 재서** 비교한다

# STaR: 스스로 만든 풀이로 스스로 학습

**Self-Taught Reasoner** (Zelikman et al., 2022) — 오늘 발표 논문 ①

```
        ┌────────────────────────────────────────┐
        │ ① 풀이 생성: 문제마다 CoT로 풀게 한다      │
        │ ② 필터: 최종 답이 맞은 풀이만 남긴다        │
        │ ③ 파인튜닝: 남은 풀이로 모델을 다시 학습     │
        └───────────────┬────────────────────────┘
                        └── ④ 더 똑똑해진 모델로 ①부터 반복
```

- 사람이 풀이를 **한 줄도 안 써줌** — 몇 개의 예시만 시드로
- 핵심 트릭: 풀이의 품질은 못 재도 **답의 정오는 잴 수 있다** ← 이게 필터

---

# STaR의 두 번째 트릭: 힌트 주고 다시 풀기

**문제:** ②에서 못 푼 문제는 학습 데이터가 안 됨 → 쉬운 문제만 배우는 함정

**해법 — rationalization:**
- 틀린 문제는 **정답을 슬쩍 보여주고** "왜 이 답인지" 풀이를 쓰게 한다
- 그 풀이를 (정답 힌트는 떼고) 학습 데이터에 추가
- 어려운 문제에서도 배울 수 있게 됨

| CommonsenseQA (GPT-J 6B) | 정확도 |
|---|---|
| Few-shot CoT | 36.6% |
| 직접 파인튜닝 (풀이 없이) | 60.0% |
| **STaR + rationalization** | **72.5%** |
| GPT-3 직접 파인튜닝 (**30× 큰 모델**) | 73.0% |

<p class="small">출처: STaR 논문 Table 1 · GSM8K도 3.1→10.7로 3배 (Table 2)</p>

# 잠깐 — 강화학습(RL) 3분 입문 ①

다음 논문(R1)을 읽는 데 필요한 건 수식이 아니라 **개념 하나**다.

**강아지에게 "앉아"를 가르친다고 하자:**
- 정답 동작을 *보여줄* 방법이 없다 (강아지는 시연을 못 따라 함)
- 대신: 이것저것 하다가 **우연히 앉으면 → 간식**
- 간식 받은 행동은 **점점 자주** 나온다. 끝.

| | 지도학습 (SFT) | 강화학습 (RL) |
|---|---|---|
| 주는 것 | **정답 시연** ("이렇게 해") | **점수만** ("그건 잘했어/못했어") |
| 배우는 것 | 시연을 흉내 내기 | 점수 받는 행동을 늘리기 |
| 한계 | 시연자보다 못함 | 시연 없이도, **시연자를 넘을 수도** |

# RL 3분 입문 ② — LLM에 적용하면

| RL 용어 | LLM에서는 |
|---|---|
| 행동(시도) | 문제에 대한 **답안 하나를 생성** (풀이 포함) |
| 보상(간식) | 그 답안의 **점수** |
| 학습 | 점수 잘 받은 **생성 방식이 강해지게** 가중치 조정 |

점수를 누가 주느냐로 갈린다:
- **사람의 선호** 점수 → RLHF (ChatGPT를 만든 그 방법)
- **채점 규칙** (정답 일치, 테스트 통과) → **RLVR** ← 오늘의 R1

> 오늘 필요한 전부: **"점수를 주면, 점수 받는 행동이 늘어난다"**
> 가중치를 *어떻게* 조정하는지(PPO 등)는 이 과목 범위 밖 — W12에서도 직관까지만

# STaR → R1: 사이 3년을 한 장으로

STaR의 필터("답이 맞으면 남긴다")를 다시 보면 — **이건 사실상 보상이다**

- 답 맞음 = 보상 1, 틀림 = 보상 0
- STaR = 그 보상으로 하는 **원시적인 RL** (논문 스스로 이 연결을 언급)

그렇다면 제대로 된 RL로, 더 큰 모델에서, 끝까지 돌리면 무슨 일이 벌어지나?

→ **DeepSeek-R1** (2025) — 오늘 발표 논문 ②

<p class="small">중간 역사(o1 등)는 비공개라 생략 — 공개된 전 과정은 R1이 처음</p>

---

# R1-Zero: 순수 RL만으로

레시피가 충격적으로 단순하다:

1. 베이스 모델(DeepSeek-V3)에서 시작 — **사람의 풀이 시연 0개**
2. 보상은 규칙 둘뿐: **정답이면 +** (수학은 채점 가능) / **형식 지키면 +** (`<think>` 태그)
3. RL을 오래 돌린다

결과 (AIME 2024, 수학올림피아드 예선급, pass@1):

| 훈련 전 | 훈련 후 | +다수결(SC) |
|---|---|---|
| 15.6% | **77.9%** | **86.7%** — 인간 참가자 평균 초과 |

<p class="small">출처: DeepSeek-R1 논문 (우리 `papers/` PDF 기준) Figure 1a</p>

# 창발: 아무도 가르치지 않은 행동

훈련이 진행되며 모델이 **스스로**:
- 응답(생각)이 점점 **길어진다** — 더 오래 생각하는 게 이득임을 발견
- 검산, 대안 탐색, **자기 교정**이 나타난다

훈련 중간의 실제 출력 (논문 Table 2, 원문 그대로):

> *"Wait, wait. Wait. That's an aha moment I can flag here.
> Let's reevaluate this step-by-step…"*

- "다시 생각해보자"를 **누구도 시키지 않았다** — 정답 보상만 줬을 뿐
- 지난주 CoT(생각을 쓰게 *하기*) → 이제 모델이 생각을 *스스로 기르는* 단계

# R1-Zero → R1: 마감 처리

R1-Zero의 부작용: 생각이 **읽기 어렵고**, 언어가 섞여 나옴 (보상에 없었으니까)

**R1** = 소량의 좋은 예시로 먼저 다듬고(SFT) → 다시 RL → 최종:

| 벤치마크 | R1 |
|---|---|
| AIME 2024 (pass@1) | 79.8% |
| MATH-500 (pass@1) | 97.3% |

교훈 두 줄:
- **능력은 RL이 만들고, 태도는 SFT가 다듬는다**
- 보상에 넣지 않은 것(가독성)은 얻지 못한다 — **보상 설계가 곧 사양서** (→ W12·W13)

# 내 루프에 어떤 모델을 넣을까

| | 일반 모델 (예: V3, 4o) | 추론 모델 (예: R1, o1) |
|---|---|---|
| 한 호출 | 빠르고 싸다 | 느리고 비싸다 (생각 토큰 값) |
| 강점 | 도구 호출·정형 작업 | 수학·계획·까다로운 판단 |
| 루프 설계 | **여러 바퀴** 돌며 관찰로 보정 | **적은 바퀴**, 한 수를 깊게 |

두 가지 설계 감각:

1. **"루프를 짧게, 생각을 길게"** — 추론 모델은 ReAct 10바퀴 대신 계획 1번+실행
2. **섞어 쓰기** — 계획은 추론 모델, 도구 호출·요약은 싼 모델 (라우팅)

> 정답은 없고 **비용–정확도 트레이드오프**가 있을 뿐 — W13에서 이걸 측정하는 법을 배운다

# 현장 노트 ① — 생각의 양은 이제 API 스위치다

추론 모델은 "생각을 얼마나 할지"를 **파라미터로** 받는다 (이름은 벤더마다):

| 벤더 | 스위치 |
|---|---|
| OpenAI | `reasoning_effort` (low / medium / high) |
| Anthropic | extended thinking `budget_tokens` |
| Google | `thinking_budget` |

실무에서 반드시 아는 것 3가지:
1. **생각 토큰도 출력 토큰으로 과금** — 안 보이는 토큰에 돈이 나간다
2. **지연 = 생각 길이** — 사용자 앞 실시간 UI엔 스트리밍·낮은 effort
3. 정형 작업(분류·추출·요약)엔 **생각 끄는 게 정답**인 경우가 많다

# 현장 노트 ② — 모델 선정, 절차로

실무 판단은 감이 아니라 **순서도**다:

```
① 이 단계, 채점(검증)이 가능한가? ── 아니오 → 싼 모델 + 사람 검토
        │ 예
② 다단계 추론·계획이 필요한가? ──── 아니오 → 싼 모델 (기본값!)
        │ 예
③ 지연·비용 예산 안인가? ────────── 아니오 → 다수결(SC)·프롬프트 개선 먼저
        │ 예
④ 추론 모델 투입 → eval로 전/후 비교 (W13)
```

- **기본값은 항상 싼 모델** — 추론 모델은 병목 *지점*에만
- "비싼 모델로 바꿨더니 좋아진 *느낌*" 금지 — **측정이 근거** (W13 하네스)

**2부 — self-consistency (`reasoning.py`):**

```python
def self_consistency(question, n=5):
    answers = []
    for _ in range(n):
        path = llm(cot_prompt(question), temperature=0.8)  # ① 경로 샘플
        answers.append(extract_answer(path))               # ② 최종 답만 추출
    return majority_vote(answers)                          # ③ 다수결
```

- ✅ 완료 기준: ① 루프가 한 바퀴 돌아 답 ② 애매한 질문에서 **N=1보다 N=5가 정확**
- 함께 기록: **호출 수·토큰 비용** — "5배 낼 가치가 있었나"까지가 오늘 실습
