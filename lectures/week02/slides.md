# 지난주와의 연결

지난주 우리는 **정의**를 세웠다("LLM이 다음 행동을 정하면 에이전트") — 그 정의의 심장이 **루프**였다.

```
목표 → [LLM] → 행동 → 결과
         ↑___________|      ← 이 화살표는 어디서 왔나?
```

오늘은 이 루프를 **역사 순서로** 따라간다:
**그냥 묻기 → 생각시키기(CoT) → 행동시키기(Act) → 둘을 엮기(ReAct).**
각 단계가 앞 단계의 약점을 고치며 나온다.

# 0단계 · 직접 질의

모델에 곱셈이나 사실을 그냥 물으면, **그럴듯하지만 틀린** 답이 나온다.

- LLM은 **다음 단어 예측기** — 곱셈 회로가 아니다
- 자릿수가 커지면 "정답처럼 생긴 숫자"를 만든다
- 모르는 사실은 **지어낸다** (환각, hallucination)

이 두 결함 — **계산 못 함**과 **환각** — 이 이후 모든 단계의 출발점이다.

# 1단계 · CoT — 추론 과정의 외부화

**Chain-of-Thought (CoT)** = 최종 답을 내기 전에 **중간 추론 과정을 텍스트로 쓰게** 하는 프롬프트 기법 (Wei et al., 2022).

```
Q. 사과 23개가 있다. 20개를 쓰고 6개를 더 샀다. 지금 몇 개?
   답만:  "9"
   CoT :  "23 − 20 = 3,  3 + 6 = 9.  답: 9"   ← 답 앞에 과정을 드러낸다
```

왜 성능이 오르나:
- 트랜스포머는 입력을 **정해진 수의 층**에 한 번 통과시켜 다음 토큰 하나를 낸다 — 즉 토큰 하나를 만드는 데 쓰는 **순차 계산의 단계 수가 고정**돼 있다
- 어려운 문제는 그 고정된 단계 안에 안 풀린다. CoT는 답을 **여러 토큰에 나눠 쓰게** 해, 토큰마다 층을 다시 통과시킨다 → 사실상 순차 계산을 여러 배로 늘리는 셈이다 (중간 토큰이 계산의 **작업 공간** 역할)
- 이 효과는 **모델이 충분히 커야** 나타난다 — 작은 규모에선 없던 능력이 일정 규모를 넘어 나타나는 현상을 **창발(emergence)** 이라 한다 (작은 모델에선 CoT가 무효하거나 오히려 해롭다)

> 가중치를 하나도 안 바꾸고 프롬프트만으로 오른다 — 다음 주(W3) 전체의 씨앗.

<p class="small">구체적 향상 폭(GSM8K 등)은 오늘 발표 ②(CoT)에서 수치로 확인한다</p>

# CoT의 약점 — 내부 지식에 갇힌다

```
Q: 2024년 노벨 물리학상 수상자의 소속 대학은?
Thought: 아마 ○○○일 것이다. 그는 △△대 소속이므로 답은 △△대.
         └ 추론의 구조는 그럴듯한데, 사실이 전부 지어냄
```

- CoT는 추론은 정리하지만 **내부(파라메트릭) 지식에만 의존**한다 — 외부 사실을 확인할 창구가 없다
- 환각 위에 논리를 쌓으면 — **정연하게 틀린다**
- ReAct 논문의 진단: CoT 오류의 최대 원인이 바로 이 환각

**해법의 방향:** 생각 중간에 **세계를 확인**하게 하자.

# 2단계 · 행동만 (Act-only)

그럼 생각을 빼고 **행동만** 시키면?

```
Act 1: Search[관련 단어]
Act 2: Search[또 검색]
Act 3: Finish[???]   ← 왜 검색했는지, 어디까지 왔는지 잊음
```

- 검색은 하는데 **의도와 진행 상태를 언어로 붙들지 못한다**
- 여러 단계 문제에서 길을 잃는다 — 그냥 묻기보다도 나쁠 수 있다

한쪽은 생각만(환각), 한쪽은 행동만(길 잃음). **둘 다 반쪽이다.**

<p class="small">Act-only가 얼마나 나쁜지의 수치는 발표 ①(ReAct)에서 확인한다</p>

---

# 3단계 · ReAct — 추론과 행동의 교차

**ReAct** = 한 루프 안에서 **추론(Reason)과 행동(Act)을 번갈아** 수행하는 방식 (Yao et al., 2022). 매 턴이 세 요소로 이뤄진다:

```
Thought      지금까지 안 것 정리 + 다음 할 일 결정
Action       도구 호출 선언   Search[...]
Observation  도구가 돌려준 사실
   └────────── 답이 나올 때까지 반복
```

- **Thought / Action / Observation** — 이 세 단어가 오늘의 핵심 키워드다
- 학습 없이 **프롬프트만으로** 작동한다 — 오늘날 거의 모든 에이전트 루프의 원형
- 지난주 정의한 그 루프가 바로 이것이다

# 교차의 작동 원리

---

# ReAct 트레이스 읽기 (논문 Figure 1)

> **Q.** Apple Remote가 원래 제어하도록 설계된 프로그램을, Apple Remote 말고 무엇으로 제어할 수 있나?

```
Thought 1: 먼저 Apple Remote가 어떤 프로그램용인지 찾자.
Action 1:  Search[Apple Remote]
Observ. 1: … Front Row 미디어 센터 제어용으로 설계됨 …

Thought 2: 그럼 Front Row를 제어하는 다른 장치를 찾자.
Action 2:  Search[Front Row]
Observ. 2: 'Front Row'를 찾을 수 없음. 유사: [Front Row (software), …]
```

**여기까지:** 문제를 쪼갰고(2홉), 필요한 사실을 세계에서 얻었고, **검색 실패조차 다음 생각의 재료**가 됐다.

# ReAct 작동의 세 원리

```
Thought 3: 소프트웨어니까 Front Row (software)를 검색하자.
Action 3:  Search[Front Row (software)]
Observ. 3: … Apple Remote 또는 키보드 기능 키로 제어 …
Thought 4: 답은 키보드 기능 키다.  →  Finish[keyboard function keys] ✓
```

1. **추론이 행동을 조준한다** — 무엇을 검색할지 Thought가 정한다
2. **관찰이 추론을 접지(ground)한다** — 지어내지 않고 사실 위에서만 생각한다
3. **실패가 정보다** — "없음"이라는 관찰이 경로를 수정한다

CoT의 환각도, Act-only의 길 잃음도 — 교차가 **서로의 약점을 메운다.**

---

# ReAct의 한계

- 내부 지식만으로 풀리는 문제에선 검색이 오히려 방해가 되기도 한다 → 실제로 CoT가 ReAct를 이기는 과제도 있다
- 그래서 최선은 흔히 **CoT와 ReAct의 결합** — 상황에 따라 섞는 것 자체가 설계 문제다

이 "정직한 결과"들 — 어디서 이기고 어디서 지는지 — 이 오늘 발표의 볼거리다.

**남는 한계 → 다음 주들:** 한 발씩 greedy라 되돌아오지 못함(→W5 계획·탐색) · 틀려도 그대로 제출(→W6 자기반성) · 생각을 얼마나 시킬지(→W3 추론 모델).

<p class="small">과제별 승패 수치(HotpotQA·Fever·ALFWorld)는 오늘 발표 ①(ReAct) Table에서 확인한다</p>

# 확인과 연결

---

# 오늘 발표에서 확인할 것

이론은 **개념의 뼈대**를 세웠다. 그 뼈대에 **증거**를 붙이는 게 발표다:

- **발표 ① ReAct** — Thought/Action/Observation의 실제 트레이스, 그리고 과제별로 언제 이기고 지는지(정직한 표)
- **발표 ② CoT** — 프롬프트만으로 얼마나 오르는지, 그 향상이 **모델 크기에 따라 어떻게 창발**하는지

발표를 들으며 스스로 물어라: *이 방법에서 한 단계를 빼면? 실패하는 입력은?* — 이게 콜드 질문이다.

# 오후 실습 — ReAct 루프 구현

오늘 배운 **Thought → Action → Observation** 루프를 while 문으로 만든다.

- 지난주 만든 두뇌(`chat`)를 루프 안에 넣고, 모델 출력을 **판정**한다: 최종 답인가, 도구 호출인가?
- 도구는 아직 없다 — 그 빈자리(→ W4)를 스텁으로 두고 루프의 골격만 완성한다
- ✅ 완료: 간단한 질문에 루프가 한 바퀴 돌아 답을 낸다

> 두뇌(W1) → **척추(W2)** → 숙고(W3) → 손(W4)로 앱이 매주 자란다.

# 요약

1. **CoT** = 생각을 밖으로 꺼내 성능을 올리지만, **눈감고 생각**한다(환각)
