# Agentless의 고발 — 에이전트의 세 가지 비용

논문이 정리한, 자율 에이전트 방식의 약점:

| 비용 | 내용 | 우리가 배운 곳 |
|---|---|---|
| **도구 설계 복잡성** | 도구 정의·사용이 조금만 어긋나도 성능↓ 비용↑ | W3 "도구 정의가 곧 프롬프트" |
| **통제 없는 계획** | 이슈 하나에 **30–40턴** — 어느 턴이 틀렸는지 디버깅 곤란 | W4 트레이스 리딩의 한계 |
| **자기반성의 한계** | 잘못된 피드백을 거르지 못하고 오류가 **증폭** | W8 "자기교정은 공짜가 아니다" |

- 요컨대: 자유도(자율성)는 성능이 아니라 **분산과 비용**으로 먼저 온다
- 그래서 저자들의 수: 자유도를 **전부 회수**해 보자

<p class="small">출처: Agentless (papers/ PDF 기준) §1</p>

# Agentless 해부 — 고정 3단계 파이프라인

```
① 국소화(Localize)   저장소 구조 → 파일 → 클래스·함수 → 수정 라인   (계층적으로 좁힌다)
② 수리(Repair)       그 위치에 후보 패치 여러 개 샘플링             (diff 형식)
③ 검증(Validate)     회귀 테스트 + LLM이 생성한 재현 테스트로 선별   (최종 패치 1개 제출)
```

- LLM이 "다음에 뭘 할지" 정하는 지점 = **0곳**. 제어 흐름은 100% 코드
- W1 스펙트럼의 **맨 왼쪽 칸** — 그런데 LLM은 매 단계 안에서 열심히 일한다 (국소화·패치 생성·테스트 생성)
- 도구도, 루프도, 계획도 없다 — 대신 **문제의 구조**(버그 수정은 늘 이 3단계)를 코드에 박았다

<p class="small">출처: Agentless (papers/ PDF 기준) §1·§3, Figure 1</p>

자율성 회수 ≠ LLM 축소 — LLM 호출은 오히려 여러 번(후보 패치 샘플링). 결정권만 회수했다.

# 결과 — 단순함이 이겼다, 3분의 1 가격으로

SWE-bench Lite (300문제), Agentless 논문 Table 1:

| 시스템 | 방식 | 해결률 | 평균 비용 | 평균 토큰 |
|---|---|---|---|---|
| **Agentless (GPT-4o)** | 고정 3단계 | **32.00%** (96/300) | **$0.70** | 78,166 |
| SWE-agent (Claude 3.5 Sonnet) | 자율 에이전트 | 23.00% | $1.62 | 521,208 |
| SWE-agent (GPT-4o) | 자율 에이전트 | 18.33% | $2.53 | 498,346 |
| RAG (GPT-4) | 검색→생성 1회 | 2.67% | $0.13 | – |

- **같은 모델(GPT-4o)로: 32.00% vs 18.33%** — 파이프라인이 에이전트를 크게 이겼다
- 비용은 **3.6배 저렴**, 토큰은 **6.4배 절약** — 당시 오픈소스 접근법 중 **1위**

<p class="small">출처: Agentless (papers/ PDF 기준) Table 1·§5.1 — SWE-agent 수치는 동 표의 리더보드 인용값</p>

# 왜 이겼나 — 그리고 소금 한 줌

**왜:**
- 논문의 관찰: 패치의 **위치 정확도가 해결률과 강하게 상관** — 승부처는 자율 탐색이 아니라 **국소화**였고, 그건 계층적 절차로 충분했다
- RAG(2.67%)와의 차이가 증거: 이긴 것은 "단순함" 자체가 아니라 **문제 구조를 아는 단순함**

**소금:**
- 리더보드 최상단은 여전히 닫힌 상용 시스템들(최고 43.00%) — Agentless는 *공개된 것 중* 1위
- 이슈→패치처럼 **절차가 알려진 과제**라서 3단계가 성립 — 구조를 모르는 열린 과제라면?
- 벤치마크 자체의 흠도 저자들이 발견: 정답 유출 4.3%, 정보 부족 10.0% (→ W13 "모든 벤치마크를 의심하라")

<p class="small">출처: Agentless (papers/ PDF 기준) Table 1·§5.1.2·§5.2</p>

# SWE-agent의 진단 — 모델이 아니라 인터페이스가 문제다

그럼 에이전트는 끝났는가? SWE-agent의 답: **에이전트가 약한 게 아니라, 사람용 도구를 쥐여준 게 문제다.**

- 셸·vim·에디터는 **사람의 눈과 손**에 맞춘 인터페이스 — LM은 화면이 없고, 스크롤을 못 하고, 무응답을 못 견딘다
- 제안: **ACI (Agent–Computer Interface)** — HCI(인간-컴퓨터 인터페이스)처럼, **에이전트 전용** 명령·피드백 형식을 설계하자
- 결과: GPT-4 Turbo로 전체 SWE-bench **12.47%** (286/2,294) — 직전 최고 기록(비상호작용 RAG **3.79%**)의 3배 이상

<p class="small">출처: Yang et al., "SWE-agent", NeurIPS 2024 · arXiv:2405.15793 (papers/ PDF 기준) §1–3·Table 1</p>

# ACI 유무 실험 — 같은 모델, 같은 루프, 인터페이스만 교체

SWE-bench Lite, 전부 GPT-4 Turbo:

| 구성 | 해결률 |
|---|---|
| RAG (상호작용 없음) | 2.67% |
| **Shell-only** — 에이전트 + 맨 리눅스 셸 | 11.00% |
| **SWE-agent** — 에이전트 + **ACI** | **18.00%** |

- 셸 → ACI: **+64% 상대 향상** — 모델도 루프도 그대로, **인터페이스만** 바꿨다
- ACI의 부품: 요약형 검색 · 100줄 파일 뷰어 · 한 방 편집 명령 + **린트 가드레일** · 관찰 이력 압축
- "하네스가 성능이다"(W2 CoT, W3 DFSDT에 이은) — 학기 테제의 **세 번째 증거, 인터페이스 편**

# 어블레이션 — 인터페이스의 네 다이얼 (기준 18.0)

| 다이얼 | 최적 (18.0) | 대안 → 해결률 |
|---|---|---|
| **편집** | 편집 명령 + 린트 가드 | 린트 제거 **15.0** ↓3.0 · 편집 명령 제거 **10.3** ↓7.7 |
| **검색** | 요약형 (결과 목록 한 화면) | 사람용 반복형(하나씩 넘기기) **12.0** ↓6.0 · 검색 없음 **15.7** ↓2.3 |
| **파일 뷰어** | 100줄 창 | 30줄 **14.3** ↓3.7 · 전체 파일 **12.7** ↓5.3 |
| **컨텍스트** | 최근 관찰 5개만 유지 | 전체 이력 **15.0** ↓3.0 |

- **더 보여주기가 해롭다** — 전체 파일·전체 이력 모두 성능↓ (W9 "컨텍스트는 선별"의 실증)

# 종합 — "에이전트냐 아니냐"는 틀린 질문이다

두 논문을 한 축에 놓으면, 이분법이 사라진다:

```
모델이 제어 ◀───────────────────────────────────────▶ 코드가 제어
 맨 셸 프롬프트        SWE-agent (ACI)        Agentless          RAG 1회
```

# 현장 노트 ② — 개선 순서: 프롬프트 → RAG → SFT → RL

출시 후 품질이 아쉬울 때, **싸고 되돌리기 쉬운 것부터**:

| 순서 | 수단 | 비용·되돌리기 | 우리가 배운 곳 |
|---|---|---|---|
| 1 | 프롬프트·도구 정의·**인터페이스(ACI)** | 분 단위 · 즉시 | W2·W3 · 오늘 |
| 2 | RAG (지식을 밖에서) | 시간 단위 | W5–6 |
| 3 | SFT (트레이스로 파인튜닝) | 일 단위 | W3·W4 (ToolLLM·STaR) |
| 4 | RL (**마지막 수단**) | 주 단위 · 고위험 | W4 (R1) |

- 3단계의 위력 (Berkeley 강의자료 기준): 405B 교사의 트레이스로 8B를 SFT → **2.0% → 76.6%**, GPT-4o(74.9)를 넘기며 **비용 1/300** — 축소·단순화도 훌륭한 "개선"이다
- 단, 이 사다리는 **W13의 평가 하네스 없이는 못 오른다** — 측정 없이는 단순화가 개선인지 퇴보인지조차 모른다

# 오후 실습: `app.py` — 전체 조립, 그리고 베이스라인과의 대결

```python
# app.py — 한 학기의 부품을 하나의 CLI로
agent    = build_agent(llm, tools, retriever, memory, guardrails)  # W1–W14 전부
```

# 오늘의 세 줄 요약
