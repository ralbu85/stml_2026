|---|---|---|

# 에이전트 정의, 다시 — 한 문장이 자란 과정

**W1의 정의:** *"LLM의 출력이 다음에 무엇을 할지를 결정하는가"* — 여전히 유효하다. 그런데:

| 주 | 정의에 붙은 살 |
|---|---|
| W2·4·7–8 | 그 '결정'은 루프·탐색·반성 속에서 일어난다 — **결정에도 구조가 있다** |
| W3·12 | 결정은 도구로 세계에 닿을 때만 의미가 있다 — **모델은 JSON을 쓸 뿐, 실행은 하네스** |
| W5–6·9–10 | 모델이 무엇을 보고 결정하나 — **보이는 것(컨텍스트)도 우리가 설계한다** |
| W13 | 좋은 에이전트라는 주장은 **점수표 없이는 공허하다** |
| W14 | 결정권을 주는 순간 **권한·보안이 정의의 일부**가 된다 |
| W15 | 그리고 가끔은 — **에이전트가 아닌 게 답이다** (Agentless) |

> 16주 뒤의 답: **에이전트 = 모델 + 하네스.** 정의의 나머지 절반은 전부 하네스에 있었다.

# 토론 — 여러분의 정의는 바뀌었는가?

> ## "학기를 통해 '에이전트'의 정의는 어떻게 바뀌었는가?"

- W1 첫 시간, 여러분이 생각했던 에이전트는 무엇이었나
- 지금 누가 "에이전트 만들었어요"라고 하면, 여러분은 **무엇부터 물어볼 것인가**
  - (루프는? 도구는? 평가는? 권한은? — 질문 목록이 곧 여러분의 새 정의다)

30초 옆 사람과 → 두어 명만 듣는다. 나머지는 발표 Q&A에서 계속.

# 최종 발표 운영 — 순서와 시간

**발표 = 자기 `docqa-agent`를 하네스 설계 관점에서 방어하는 것** (요약이 아니라 방어)

| 구간 | 시간 | 내용 |
|---|---|---|
| ① 라이브 데모 | 4분 | 자기 에이전트가 실제로 일하는 장면 (사전 준비한 데모 스크립트) |
| ② 점수표 방어 | 4분 | `eval/harness.py` 결과 — 정확도·비용·지연·재현성 |
| ③ 설계 선택 방어 | 2분 | "왜 이렇게 만들었나" 1–2개 (예: top-k, 재시도 예산, 컨텍스트 정렬) |
| ④ Q&A + 동료 평가 | 2분 | 교수·청중 질문, 평가지 기입 |

- 편당 **12분, 하드 스톱** — 순서는 사전 공지본 그대로, 중간 휴식 10분
- 데모가 죽으면? **그것도 발표다** — 트레이스를 열어 어디서 죽었는지 읽으면 만점 감이다

마지막 줄이 진심임을 강조: 이 수업에서 트레이스 리딩(W4)은 디버깅의 기본 절차였다. 라이브 실패를 읽어내는 게 최고의 이해 증명.

# 현장 노트 (마지막) — 발표 방어 절차: 주장 → 점수표 → 한계

실무의 시스템 리뷰·논문 rebuttal과 같은 3단 구조로:

1. **주장** — "내 에이전트는 X를 잘한다"를 *한 문장*으로 (W1 이후 계속 연습한 그 압축)
2. **점수표** — 주장을 `eval/harness.py` 수치로 뒷받침. **베이스라인 대비**(W15의 단순 파이프라인 비교)가 있으면 최고
3. **한계** — 실패하는 입력을 *스스로* 먼저 보인다 — 남이 찾기 전에

**교수 콜드 질문 (학기 내내 그 3종, 이번엔 여러분의 시스템에):**
"[모듈 X] 빼면 점수 어떻게 되나?" · "처음부터 다시 만든다면 뭘 바꾸나?" · "이게 실패하는 질문을 하나 만들어봐라"

# 동료 평가 + 보조 읽기

**동료 평가 (청중 전원, 발표마다):**

| 항목 | 질문 |
|---|---|
| 데모 | 실제로 동작하는가 — 재현 가능해 보이는가 |
| 점수표 | 수치가 주장을 뒷받침하는가 (채점 방식도 밝혔는가 — W13의 교훈) |
| 설계 방어 | "왜"에 답했는가 — 선택의 트레이드오프를 아는가 |

각 1–5점 + 한 줄 코멘트 → 수합해 발표자에게 익명 전달. **제출물: 데모 + 평가 리포트** (오늘까지)

**보조 읽기 (발표 대상 아님):** *The Rise and Potential of LLM Based Agents: A Survey* — Xi et al., 2023 · [arXiv:2309.07864](https://arxiv.org/abs/2309.07864) (`papers/W16_LLM-Agents-Survey-Xi_2309.07864.pdf`) — 오늘 회고의 brain/perception/action 원전. §4 open problems를 자기 연구와 연결해 볼 것

# 마치며 — 이 분야는 계속 움직인다

이 강의의 절반은 **2022–2025년 논문**이었다. 내년 이 수업은 다른 논문을 읽을 것이다. 남는 것은:

- **계속 읽는 법** — arXiv(cs.CL·cs.AI) 새 논문, 주요 랩 블로그(Anthropic·OpenAI·DeepMind), Berkeley LLM Agents 강좌, 그리고 **트레이스를 직접 열어보는 습관**
- **계속 만드는 법** — 새 기법이 나오면? 여러분 repo의 모듈 하나를 갈아끼우고 `eval/harness.py`로 전후 비교. 그게 이 분야의 과학적 방법이다
- **의심하는 법** — 수치엔 채점기를 묻고, 데모엔 실패 입력을 묻고, "에이전트"라는 말엔 루프·도구·권한을 물어라

> 여러분의 다음 논문에, 이 하네스 감각을.
> — 한 학기 수고 많았습니다. 이제, 발표 시작합니다.
