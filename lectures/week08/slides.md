# W7 실습의 마지막 장면

```
Plan: ① 논문에서 1저자 찾기 → ② 그 저자의 소속 찾기
Step ①: search("1저자") → 관련 없는 청크    ← 검색이 빗나갔다
Step ②: ... Final Answer: "스탠퍼드 대학"   ← 그럴듯하다. 그리고 틀렸다.
(루프 종료. 아무도 답을 다시 보지 않았다.)
```

- `planner.py`는 계획을 세우고, 루프는 실행하고 — **한 번 답하면 끝**
- 우리 에이전트에게 아직 없는 것: **자기 답을 의심하는 회로**
- 사람은 틀리면 다시 본다 — 오늘, 그 "다시 보기"를 루프에 단다

# 자기교정의 위치 — 가중치 안과 하네스 안

W4 발표 논문 DeepSeek-R1: *"Wait, wait. Wait. That's an aha moment…"* — 자기교정이 RL로 창발

| | R1의 자기교정 (W4 발표) | 오늘의 자기교정 (W8) |
|---|---|---|
| 어디에 있나 | **가중치 안** (학습됨) | **하네스 안** (루프로 만듦) |
| 만드는 비용 | 대규모 RL 훈련 | 프롬프트 + for 루프 |
| 고칠 수 있나 | 재훈련 필요 | 오늘 오후에 고친다 |

- 가중치를 못 건드리는 우리가 같은 행동을 **밖에서** 만드는 것 — 오늘의 논문 제목이 그래서 "**verbal** reinforcement learning"이다
- 학기 내내 반복 중인 테제: 하네스가 성능이다 — 오늘의 반성 루프도 그 증거다

## 생성 → 비평 → 개선

---

# Self-Refine — 모델 하나, 역할 셋

```
초안:   y₀ = M(x)                       ← 생성자
반복:   fb = M(x, y)                    ← 비평자: 같은 모델, 다른 프롬프트
        y' = M(x, y, fb)                ← 수정자: 피드백을 반영해 다시 쓰기
정지:   피드백이 "문제 없음"이거나 예산 소진
```

- 추가 학습 **0** · 모델 **1개** · 프롬프트 **3벌** — 그게 전부
- W1에서 이름만 들었던 워크플로우 패턴의 다섯 번째, **evaluator–optimizer**가 바로 이 구조 (오늘이 그 주차)
- 관건은 정지 조건 — 언제까지 돌릴 것인가? (현장 노트에서)

# 피드백은 구체적이어야 작동한다

같은 루프, 피드백 문장만 바꿨을 때 (ChatGPT·GPT-3.5):

| 과제 | 구체적 피드백 | 뭉뚱그린 피드백 | 피드백 없음 |
|---|---|---|---|

# Reflexion — 반성문을 쌓는 에이전트

```
Actor (Mₐ)            ReAct로 행동/답 생성        ← W4에서 만든 그 루프
Evaluator (Mₑ)        궤적을 채점: 성공? 실패?    ← 테스트·휴리스틱·EM
Self-Reflection (Mₛᵣ)  실패 원인을 말로 요약       ← "…를 든 줄 알았지만 아니었다"
Memory (mem)          반성문 최대 3개 보관 → 다음 에피소드 프롬프트에 주입
```

- Self-Refine이 **답을** 고친다면, Reflexion은 **다음 판 전체**를 고친다 — 에피소드 단위 재시도
- "**verbal RL**": 보상 스칼라(0/1)를 *말로 된 반성문*으로 바꿔 컨텍스트에 축적 — **gradient 없이** 시도마다 나아진다
- 가중치는 그대로, 배운 것은 전부 **메모리(컨텍스트)에** — W10 메모리의 예고편

<p class="small">출처: Reflexion 논문 (우리 papers/ PDF 기준) §3·Figure 1</p>

# 숨은 주인공은 반성문이 아니라 **채점기**다

Reflexion이 과제마다 실제로 쓴 Evaluator:

| 과제 | Evaluator (누가 실패를 판정했나) |
|---|---|
| 프로그래밍 | 모델이 **스스로 생성한 단위 테스트** 최대 6개 — 실행해서 판정 |
| ALFWorld | 수제 휴리스틱 — 같은 행동 3회 반복 or 30스텝 초과면 실패 |
| 추론 QA | 정답 문자열 일치 (EM) |

- 셋 다 "모델의 느낌"이 아니라 **실행·규칙 기반의 외부 신호**
- 그리고 반례: MBPP에서는 **80.1 → 77.1로 하락** — 잘못 통과시키는 테스트(위양성)가 16.3%나 되자, 반성이 멀쩡한 코드를 망가뜨렸다 (HumanEval의 위양성은 1.4% → 91.0)

# 반전 — "다시 생각해봐"는 안 된다

오라클(정답 여부) 없이 GPT-4에게 자기 답을 재검토시키면:

| 조건 | 결과 |
|---|---|
| 자기교정, 오라클 없음 | 95.5 → **89.0** (하락) · CSQA 75.8 → **38.1** (붕괴) |
| 오라클이 "틀렸다"고 알려줄 때만 반성 | 95.5 → **97.5** (상승) |

- 맞은 답을 **의심해서 틀리게 고친다** — 자기교정의 병목은 *수정*이 아니라 **탐지**
- 모델은 자기 답의 채점자가 될 수 없다: 틀린 줄 알았다면 애초에 안 틀렸다
- 외부 신호(테스트 통과·도구 에러·검색 품질·정답 체크)가 있을 때만 반성이 작동한다

# 오늘의 두 논문도 정확히 같은 말을 한다

**Self-Refine, 수학이 안 늘던 이유 (아까의 수수께끼):**
- 비평자(ChatGPT) 피드백의 **94%가 "everything looks good"** — 오류를 못 *본다*
- 외부 소스가 정오만 알려주면: GPT-3.5 64.1 → **68.9** (+4.8) — 같은 루프가 살아난다

**Reflexion, 스스로 한 절제 실험 (HumanEval Rust 최난 50):**
- 단위 테스트를 빼고 반성만 시키면 **52% < 베이스라인 60%** — 오라클 없는 반성은 멀쩡한 코드에 "해로운 수정"을 가한다

> Reflexion이 성공한 건 반성 *때문만*이 아니다 — **evaluator가 있는 반성**이었기 때문이다.

<p class="small">출처: Self-Refine 논문 §3.3·Table 9 / Reflexion 논문 §4.3 Table 3 (우리 papers/ PDF 기준)</p>

# 현장 노트 ① — 피드백 소스 위계

재시도에 붙일 피드백, 어디서 구하나 — **위일수록 믿을 만하고, 아래일수록 싸다**:

| 위계 | 피드백 소스 | 예 |
|---|---|---|
| 1 | **테스트·검증기** (실행 기반) | 단위 테스트, 정답 체크, 스키마 검증, 검색 결과 관련성 |
| 2 | **린터·컴파일러·타입체커** (규칙 기반) | 문법 오류, 타입 불일치 |
| 3 | **다른 LLM의 비평** | 별도 프롬프트의 채점자 모델 |
| 4 | 자기비평 | "다시 생각해봐" — 오늘 본 그 함정 |

- 설계 원칙: **확보 가능한 가장 높은 위계를 먼저** — 없으면 만든다 (Reflexion은 테스트를 *생성*해서라도 1층을 확보했다)
- 단, MBPP의 교훈: 1층도 **오염되면**(위양성 16.3%) 독이 된다 — 채점기부터 검증하라

# 현장 노트 ② — 반성 루프 설계 절차 (4문항)

1. **무엇이 피드백인가?** — 위계 최상위 확보. 자기비평뿐이라면 루프를 달지 마라
2. **몇 번까지?** — 재시도 예산 `max_retries` (보통 2–3). 재시도 1회 = 비용·지연 1배 추가
   — Self-Refine도 이득 대부분이 **첫 1–2회 반복**에 몰린다 (수확 체감)
3. **stop 조건 3종** — ① 검증 통과 ② 예산 소진 ③ **같은 피드백 반복** (같은 지적 2번 = 더 돌려도 안 나온다)
4. **포기하면?** — 최선 시도 반환 or **사람에게 에스컬레이션** (W7 승인 게이트의 짝)

> evaluator–optimizer 패턴의 실무 규격: 피드백 소스 · 예산 · stop · 탈출구, 네 칸을 채워야 설계 완료

# 오후 실습: `reflect.py` — 실패를 다음 시도의 입력으로

```python
def reflect_and_retry(question, verify, max_retries=3):
    feedback = None
    for attempt in range(max_retries):
        answer = agent_loop(question, feedback)   # 피드백을 프롬프트에 주입
        ok, why = verify(answer)                  # ← 외부 검증기 (자기비평 아님!)
        if ok:
            return answer
        feedback = f"이전 시도: {answer}\n실패 이유: {why}\n고쳐서 다시."
    return answer                                 # 예산 소진 — 최선을 반환
```

- 설계 원칙 = 오늘의 반전: `verify`는 **위계 1–2층**(정답 체크·형식 검증·검색 결과 검증)에서
- 대상 시나리오: 검색이 빗나간 실패 → 피드백 → 재시도 (도입의 실패 트레이스에 대한 처방)
- ✅ 완료 기준: 처음 틀린 답을 재시도로 교정한다 (`tests/test_week08.py`)
- **발표 2편:** Reflexion(반성문을 쌓는 verbal RL) · Self-Refine(생성→비평→개선)

# 오늘의 세 줄 요약

1. **실패도 Observation이다** — 실패를 말로 요약해 다음 시도에 주입하면, gradient 없이 학습처럼 작동한다 (Reflexion: GPT-4 80.1→**91.0**, ALFWorld 130/134)
2. **반성 루프 = evaluator–optimizer** — 생성→비평→개선, 학습 0·프롬프트 3벌 (Self-Refine 평균 ~20%p)
3. 단, **오라클 없이는 안 된다** — 자기교정의 병목은 탐지. 피드백 위계의 최상위(테스트·검증기)를 확보하고, 예산과 stop 조건을 설계하라

**다음 주 (W9. 컨텍스트 엔지니어링):**
검색(W5–6)·계획(W7)·반성(W8)이 쌓아 올린 컨텍스트를 희소 자원으로 관리한다. 중간 데모 체크포인트.
