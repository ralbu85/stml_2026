# 강의자료 집필 규정

이 문서는 이 리포의 모든 강의자료(슬라이드·노트북·실습·문서)에 적용되는 규정이다.
자료를 새로 만들거나 수정할 때 이 규정을 먼저 적용하고, 완성 후 §8 체크리스트로 검수한다.

---

## 1. 이론과 실습의 분리

| 매체 | 역할 | 담지 않는 것 |
|---|---|---|
| 이론 덱 (`lectures/*/slides.md`) | 개념·키워드의 논리적 전개. 정의와 원리 | 코드 설명, 구체 수치·실험 디테일(→발표 위임) |
| 실습 (`labs/`, 노트북) | 구현과 실행. 코드가 주인 | 이론의 재서술 |
| 논문 발표 | 구체 수치·실험·검증 | — |

- **노트북은 실습 자료다.** 이론 강의를 노트북으로 대체하거나, 노트북 마크다운 셀에서 이론을 다시 전개하지 않는다.
- 실습에서 개념이 필요하면 정의를 **한 줄로 재인용**하고 해당 덱을 참조 표시한다. 계보·동기·서사는 덱의 몫이다.
- 이론 덱에는 코드 블록을 넣지 않는다. 필요하면 개념 그림·표·의사구조로 대체하고 구현은 실습으로 위임한다.
- **실물 발췌는 허용된다** (2026-08, "노트를 더 프랙티컬하게"): 강의노트에는 그 주 실습이 실제로 쓰는 프롬프트 원문·도구 스키마·호출 트레이스 같은 짧은 실물을 코드 블록으로 인용할 수 있다. 구현 코드 전체는 여전히 실습에만 둔다. 실물을 인용하면 그 각 부분이 본문의 어느 원리를 실행하는지 한 문장으로 잇는다.

## 2. 문체 — 모든 매체 공통

**문어체 평서문으로 쓴다.** 강의자료는 교재이지 발화 대본이 아니다.

금지 목록:

| 금지 | 예 |
|---|---|
| 청유형 | "~하자", "~해 보자", "나란히 본다", "따라가 보자" |
| 질문형 전환·수사의문문 | "그럼 생각을 빼고 행동만 시키면?" |
| 은유·서사적 수사 | 심장, 씨앗, 주인공, 반쪽, 물건, 두뇌·척추·손 |
| 구어적 표현 | "그냥", "아예", "원래 그런", "~하는 셈이다", "던지면", "그랬더니" |
| 우회·대구 화법 | "X는 그대로이고, 달라지는 것은 Y다", "선택지는 둘이다 ~ 원칙은 후자다", "규모로 간다", "길이 열린다" 류. 주어와 술어로 직접 진술한다("function calling의 단계는 수제 규약과 동일하다. 신뢰성은 더 높다") |
| 대시(—) 연결 남용 | 문장을 대시로 이어 붙이는 전개. 논리 접속어로 잇는다 |
| 감탄·영탄 | "!", "정연하게 틀린다" 류의 경구체 |
| 취업·효용 세일즈 | "채용공고에 나오는 용어", "회의에서 여러분의 발언이 된다" 류. 실무 용어·프로세스는 현장 노트에서 내용으로 다루되, 커리어 효용으로 동기부여하지 않는다 |
| 진행·역할 규정 문장 | 본문 문장은 개념에 대한 진술이어야 한다. 전개 구조를 해설하는 자기 언급 — "기준선이다", "이후 주차의 뼈대다", "모든 주차의 기본기다", "이 관찰이 출발점이다", "오늘의/오늘 이후" 류 — 은 대학 교재에 없는 문장이므로 통째로 삭제한다(고쳐 쓰는 것이 아니라). 상호참조는 괄호 표기 "(→ W9)"로만, 진행 멘트는 주석(대본)에만. 구조 슬라이드('오늘의 지도'·발표/실습 연결·다음 주 예고)는 예외 |

- 비유가 직관에 필요하면 쓸 수 있으나, 반드시 **표준 학술용어와 정확한 메커니즘으로 받는다.** 비유로 끝나는 문단은 미완성이다.
- **강조 규칙:** 볼드는 정의되는 용어의 최초 등장 1회만. 한 문단에 볼드 2개를 넘기지 않는다. 이탤릭 강조는 쓰지 않는다.
- **개수를 제목·라벨에 박지 않는다.** "네 단계 계보", "세 가지 원리" 금지. 항목 수는 표·목록에서 자연히 드러난다. 순서·계보는 화살표(A → B → C)로 보인다.

## 3. 개념 전개 — 정의 우선

핵심 개념의 전개 순서는 고정이다:

**정의 → 관계·논리 → 예시 → 한계·연결**

- 첫 등장 용어는 그 자리에서 정의한다: `**용어(English term)** = 한 문장 정의` (Wei et al., 2022 형식의 출처 병기).
- 정의 없이 용어부터 쓰지 않는다. 뒤 주차에서 정의할 용어(예: 하네스→W9)는 앞 주차에서 결론 용어로 앞세우지 않는다.
- **예시는 생략하지 않는다.** 특히 형식이 핵심인 개념(CoT 프롬프트, 함수 호출 스키마 등)은 실제 예시 한 조각을 반드시 보인다. 정의만 있고 예시가 없으면 미적용으로 간주한다.
- 대학원 수준의 학술적 정확성을 유지한다. 수식 유도는 발표로 넘기더라도 표준 용어와 원리는 강의에서 정확히 짚는다.

## 4. 장의 구조 — 자기완결·동기·절차

장 단위 자료(`notes.md`와 그로부터 만드는 덱)에 적용한다. (2026-07, 4장 검수에서 확립)

**자기완결.** 각 장은 그 장만 읽고 이해되도록 쓴다. 타 장의 결과·사례를 빌려 올 때는 그 자리에서 한두 문장으로 재서술하고, 위치는 괄호 "(→ 2.4)"로만 표시한다. 재서술 없는 참조("2.4의 사례", "3.6의 STaR와 같은 구조")는 설명을 참조로 대체한 것이므로 금지한다. 판정 기준: 참조 괄호를 전부 지워도 모든 문장이 성립해야 한다.

| 위반 | 수정 |
|---|---|
| "모델은 그럴듯한 전제를 지어내고(2.4의 Apple Remote 사례), …" | "모델은 외부 사실을 확인할 경로가 없어 그럴듯한 전제를 생성한다. Apple Remote가 제어하는 프로그램을 묻는 질문에서 틀린 전제 위에 정합한 추론을 쌓아 오답에 이르는 사례를 보였다(→ 2.4)." |

**동기 우선.** 장치·설계 원칙·형식(규약, 실패 처리 정책, 스키마 규칙 등)은 그것이 없을 때 생기는 구체적 실패를 먼저 보인 뒤 도입한다. 전개 순서: 실패 현상 → 소박한 접근과 그 한계 → 장치 → 장치가 실패를 제거하는 방식. 동기 없이 결론부터 선언하는 전개("설계 원칙은 다음과 같다")는 미완성이다. §3(정의 우선)과의 결합: 장치의 필요는 실패로 세우고, 장치의 용어는 등장 즉시 정의한다.

**절차의 명세.** 다단계 절차(규약·루프·알고리즘)는 한 곳에서 번호 목록으로 완결한다. 각 단계는 이름을 갖고, 담당(모델/코드)·입력·출력·실패 시 행동을 명시한다. 이후의 본문과 절 제목은 단계를 이름으로 부른다. ①②③ 류 기호를 본문의 참조 체계로 쓰지 않는다 — 독자를 앞의 표로 되돌려 보내는 역참조 구조("4.5 단계 ③④⑤", "판단(②)")는 금지한다.

**전달 우선.** 분량의 기준은 이해다(2026-07-13, 분량 제한 규칙 폐기). 개념이 정확히 이해되는 데 필요한 전개·예시·재서술을 분량을 이유로 줄이지 않는다. 줄이는 대상은 이해에 기여하지 않는 중복 해설과 장치뿐이다.

**검수 관점.** 완성 후 "이 장만 처음 읽는 학생이 막히는 지점"을 나열하는 검수 패스를 별도로 수행하고 반영한다.

## 5. 슬라이드 규정

- **제목은 명사구.** 서술형(-한다/-이다)·질문형(-인가/-왜)·구어·비유 제목 금지. 부제가 필요하면 "개념명 — 짧은 명사구".
- 발화 예시·진행 지시·타이밍은 HTML 주석(`<!-- -->`)에만 둔다. 본문에는 넣지 않는다. 주석 안은 대본이므로 구어 허용.
- 오늘의 지도(분 단위 배분표)와 마무리 연결 슬라이드는 유지한다.
- 분량의 기준은 이해다(§4 전달 우선). 개념 수·슬라이드 수를 상한으로 두지 않되, 이해에 기여하지 않는 장치는 늘리지 않는다.

## 6. 노트북·코드 규정

**분량과 구성.** 실습 노트북은 실습 시간(80분)을 채우는 완결된 랩이다. 함수 하나 구현하고 끝나는 통과 의례가 아니라 다음 단계를 갖춘다:

준비 → 현상 관찰(왜 이 구현이 필요한가를 실행으로 재현) → 구현·검증 → 자동화·테스트 → **측정 가능한 개선 과제**(수치를 정의하고 프롬프트·코드를 다듬어 수치를 올리는 과제 1개 이상) → 연습문제(예측→실행→확인 형식) → 완료 기준

**참고자료 조사 의무.** 실습을 설계하기 전에 `materials/repos/`에서 해당 주제의 기존 실습·과제를 조사하고 차용한다 — 특히 DeepLearning.AI/Andrew Ng(프롬프트 작성 중심 과제, 학습목표→빌드→테스트 구조), HF agents-course(현상 재현 실험), anthropic-cookbook(패턴 레시피). 차용한 출처는 노트북 헤더에 명기한다.

**셀 구조.** 한 단위는 다음 3셀 패턴을 따른다:

1. 마크다운 — 이 셀이 무엇을 확인하는지 2–4문장(§2 문체 적용, 정의는 한 줄 재인용+덱 참조)
2. 코드 — 실행 대상
3. 마크다운 — 결과 해석 1–3문장 (해석이 자명하면 생략 가능)

**코드는 교재 품질로 쓴다.**

- 주석은 코드가 보여주지 못하는 제약·의도만 서술한다. 서사·비유·예고("오늘은 X가 주인공") 금지.
- 트릭 금지: mutable default 인자로 상태 유지(`def f(_step=[0])`), 문자열 매칭 분기에 박힌 매직 상수 등. 학생이 따라 쓸 코드다.
- 상수는 이름을 붙여 셀 상단에 모은다.
- 모의 장치(폴백·스텁)는 최소화한다. 쓸 경우 실제 경로와 파일·함수 수준에서 분리하고, 모의임을 첫 줄 주석으로 명시한다.
- docstring은 한 줄 평서문: 입력 → 출력.

## 8. 검수 체크리스트

자료 완성 후 다음을 확인한다:

- [ ] 이론 덱에 코드 블록이 없고, 노트북에 이론 재서술이 없다 (§1)
- [ ] 청유형·질문형 전환·은유·구어 표현이 본문에 없다 (§2)
- [ ] 볼드가 용어 최초 정의에만 쓰였다 (§2)
- [ ] 제목·라벨에 개수 나열이 없다 (§2)
- [ ] 모든 핵심 용어가 첫 등장에서 `**용어(English)** = ...`로 정의된다 (§3)
- [ ] 형식이 핵심인 개념마다 실제 예시가 붙어 있다 (§3)
- [ ] 타 장 참조가 전부 그 자리 재서술 + 괄호 표기이고, 괄호를 지워도 문장이 성립한다 (§4)
- [ ] 모든 장치·설계 원칙이 그것이 없을 때의 실패를 먼저 보인 뒤 도입된다 (§4)
- [ ] 다단계 절차가 이름 붙은 번호 목록으로 한 곳에서 완결되고, ①② 기호 역참조가 없다 (§4)
- [ ] "이 장만 처음 읽는 학생이 막히는 지점" 검수 패스를 수행했다 (§4)
- [ ] 슬라이드 제목이 전부 명사구다 (§5)
- [ ] 노트북 코드에 서사 주석·트릭·이름 없는 매직 상수가 없다 (§6)
