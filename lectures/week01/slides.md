# 0–5′ · 왜 지금 에이전트인가

---

# 2022년의 AI vs 지금의 AI

**2022 — 챗봇:** 질문 → 답변. 끝.

**지금 — 일하는 AI:**
- **Deep Research** — 질문 하나에 수십 개 웹페이지를 *스스로 찾아 읽고* 보고서 작성
- **Claude Code** — 버그 리포트를 받아 코드를 *읽고, 고치고, 테스트 돌리고*, 실패하면 다시
- 항공권 예약, 실험 데이터 정리, 논문 서베이 …

**같은 종류의 언어모델인데, 무엇이 달라졌나?** ← 이 과목 전체의 질문

# 차이는 모델이 아니라 **구조**다

<div style="display:flex; gap:2em;">
<div style="flex:1">

**챗봇**
```
질문 → [LLM] → 답변

- 1회 호출

</div>

```
- 여러 번 호출 (루프)
- 도구로 세상을 관찰·조작
- 결과를 보고 다음 수를 결정

</div>

# 5–15′ · 정의와 스펙트럼 · 폼팩터

# LLM 단독의 세 가지 한계

1. **지식이 멈춰 있다** — 학습 시점 이후를 모른다. 여러분 랩의 내부 문서는 영원히 모른다
2. **행동할 수 없다** — 계산기 하나 못 두드리고, 파일 하나 못 연다. 말만 한다
3. **한 번 말하고 끝** — 틀린 걸 스스로 확인하고 고칠 기회가 없다

→ 에이전트는 이 세 가지를 각각 **검색(W7–10) · 도구(W4) · 루프(다음 주)** 로 푼다

# 에이전트 = LLM + 도구 + 루프

```
        ┌─────────────────────────────┐
        │  LLM (두뇌: 추론·결정)        │
        └──────┬──────────────▲───────┘
       행동 선택│              │관찰 결과
        ┌──────▼──────┐  ┌────┴───────┐
        │ 도구 (손발)   │→│ 환경/세계    │
        │ 검색·계산·API │  │ 문서·웹·OS  │
        └─────────────┘  └────────────┘
```

- LLM은 **텍스트로 행동을 선언**할 뿐 — 실제 실행은 우리가 짜는 코드(하네스)가 한다
- 이 그림의 모든 상자를 학기 중 직접 구현한다

# 자율성 스펙트럼 — 이분법이 아니다

| 단계 | 예 | LLM이 결정하는 것 |
|---|---|---|
| 고정 파이프라인 | 번역→요약→저장 | 없음 (내용만 생성) |
| 라우터 | 문의를 A/B팀에 분류 | **분기 1회** |
| 제한된 루프 | 테스트 통과까지 코드 수정 (최대 5회) | **반복·중단** |
| 자율 에이전트 | "이 논문 서베이해줘" | **계획 전체** |

- 오른쪽으로 갈수록: 유연성 ↑ / 예측가능성 ↓ / 비용 ↓? **아니, 비용 ↑**
- 실무 원칙 (W15에서 다시): **필요한 만큼만 오른쪽으로**

# 그런데 에이전트는 챗봇인가? — 폼팩터 4형태

정의(LLM이 제어 흐름을 결정)는 **겉모습과 무관**하다. 같은 엔진이 네 가지 껍데기로 온다:

| 형태 | 예 | 상호작용 단위 |
|---|---|---|
| ① 대화형 (챗봇) | ChatGPT, 상담 봇 | 메시지 주고받기 |
| ② 위임형 (백그라운드) | Deep Research, 코딩 에이전트 | **과업 맡기기 → 결과물 검토** |
| ③ 임베디드 | IDE 속 코파일럿, 문서 편집기 보조 | 작업 현장 안에서 호출 |
| ④ 헤드리스 (부품) | 파이프라인 속 에이전트, 에이전트가 부르는 에이전트 | API — 사람 없음 |

- 챗봇은 **첫 형태였을 뿐** — 무게중심은 ②·③으로 이동 중 ("대화"→"위임+검토")
- 이 수업이 가르치는 것 = 네 형태 공통의 **엔진**(루프·도구·기억). 껍데기는 마지막에 씌운다

# 에이전트 해부도 — SDK 문서의 언어로

모든 프레임워크·API 문서가 에이전트를 이 **4부품**으로 말한다:

| 부품 | 실무 용어 | 우리 앱에서 |
|---|---|---|
| 두뇌 | **Model** (+ temperature, context window) | `llm.py` (오늘!) |
| 지시 | **Instructions** = 시스템 프롬프트 (역할·규칙·어조) | 프롬프트 템플릿 |
| 손발 | **Tools** (함수 스키마 목록) | `tools.py` (W4) |
| 기억 | **Memory** (대화 히스토리 + 외부 저장) | `memory.py` (W10) |

대화는 **역할(role)** 이 붙은 메시지 목록: `system / user / assistant / tool`
**context window** = 모델이 한 번에 볼 수 있는 최대 토큰 (W9의 주인공)

# 언제 에이전트를 쓰나 — 실무 체크리스트

**쓴다** (MS ai-agents-for-beginners 기준):
- ☑ **열린 문제** — 풀이 경로를 미리 코드로 못 박을 수 없다
- ☑ **다단계 + 여러 도구** — 단일 조회·생성으로 끝나지 않는다
- ☑ **개선 여지** — 피드백·환경 신호로 점점 나아져야 한다

**안 쓴다:**
- ☒ 절차가 고정돼 있다 → 워크플로우가 더 싸고 안정적
- ☒ 오류 허용도가 낮은데 검증 수단이 없다
- ☒ 단발 질의응답이다 → 그냥 LLM 1회 호출

# 업계 공용 어휘 — 워크플로우 패턴 5종

Anthropic "Building Effective Agents"의 분류 — 실무 문서·채용공고에 그대로 나오는 말:

| 패턴 | 한 줄 | 이 과목에서 |
|---|---|---|
| **Prompt chaining** | 출력→다음 입력, 직렬 연결 | W5 계획 |
| **Routing** | 입력을 분류해 다른 경로로 | W8 적응형 검색 |
| **Parallelization** | 병렬 호출 후 취합(투표 등) | **W3 self-consistency** |
| **Orchestrator–workers** | 중앙이 하위 작업 분배 | W11 멀티에이전트 |
| **Evaluator–optimizer** | 생성↔평가 반복 | W6 자기반성 |

이 5개는 **워크플로우** (경로를 사람이 설계) — **에이전트**는 그 너머(경로를 LLM이 결정).
16주 뒤 여러분은 이 표 전부를 **직접 구현한 상태**가 된다.

# 오후 실습: 첫 부품 `llm.py` — 루프의 ①번을 만든다

```python
while steps < MAX_STEPS:
    reply = llm(history)              # ① ← 오늘 만드는 것 (chat 래퍼)
    if is_final_answer(reply):        # ② 종료 판정         (다음 주)
        return extract_answer(reply)
    obs = run_action(reply)           # ③ 행동 실행 → 관찰   (W4)
    history += [reply, obs]           # ④ 관찰을 붙이고 반복
```

- 오늘: 환경 세팅(Python 3.10+·aisuite·키/Ollama) → **원시 HTTP 호출로 API 내부 확인** → `chat()` 채우기
- ✅ 완료 기준: 원시 HTTP와 내가 채운 `chat()` 양쪽으로 같은 질문에 답을 받는다
- 이 루프 전체(②)는 **다음 주에 직접 짠다** — 오늘은 두뇌 연결까지

**발표:** 오늘은 교수 시연 (Self-Consistency — "여러 번 생각시키고 다수결", W3 예고편)
여러분 차례는 다음 주(ReAct·CoT)부터 — 오늘 시연이 그 형식의 모범입니다.

# 오늘의 세 줄 요약

1. **에이전트 = LLM + 도구 + 루프** — 판별 기준은 "LLM의 출력이 다음 행동을 결정하는가"
2. 자율성은 **스펙트럼** — 필요한 만큼만 오른쪽으로 (전부 에이전트일 필요 없다)
3. **챗봇은 껍데기 중 하나** — 대화·위임·임베디드·헤드리스, 엔진(이 수업의 내용)은 공통

**다음 주 (W2. CoT → ReAct):**
오늘 "루프가 에이전트를 만든다"고 했다 — 그 루프의 **원전(ReAct)** 을 뜯어 읽고, 직접 짠다.
(첫 학생 발표: ReAct·CoT)
