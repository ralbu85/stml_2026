# 오늘의 지도 (이론 25분)

| 분 | 무엇을 | 남길 개념·키워드 |
|---|---|---|
| 0–5 | 챗봇과 무엇이 다른가 | 모델이 아니라 **구조**가 바뀌었다 |
| 5–13 | 에이전트란 무엇인가 | 정의 · 구성요소 · **자율성 스펙트럼** |

# 2022년의 AI vs 지금의 AI

**2022 — 챗봇:** 질문 → 답변. 끝.

**지금 — 일하는 AI:** Deep Research는 스스로 수십 개 웹페이지를 찾아 읽고 보고서를 쓴다. Claude Code는 버그를 받아 코드를 읽고·고치고·테스트하고, 실패하면 다시 한다.

> 모델의 종류는 거의 같다. **무엇이 이 차이를 만들었나?** — 이 질문이 16주 내내 이어진다.

# 에이전트란 무엇인가

---

# 정의 — 에이전트란 무엇인가

**제어 흐름(control flow)** = 다음에 무엇을·언제·몇 번 실행할지 정하는 결정.

> **에이전트** = 이 제어 흐름을 **LLM의 출력이 결정하는** 시스템.
> 개발자가 제어 흐름을 미리 고정하면 **워크플로우(workflow)** 다.

- 판별 기준은 능력이 아니라 **결정권의 소재**다 — "검색을 하니까 에이전트"가 아니라 **검색할지 말지를 LLM이 정할 때** 에이전트다
- 그래서 같은 도구를 써도, 순서를 사람이 짰으면 워크플로우·모델이 정하면 에이전트

# 구성 요소 — 에이전트를 이루는 네 부품

어떤 프레임워크 문서를 열어도 에이전트는 이 **네 부품**으로 설명된다:

| 부품 | 무엇 | 키워드 |
|---|---|---|
| **두뇌** | 판단·결정을 내리는 모델 | Model, temperature, context window |
| **지시** | 역할·규칙·어조를 주는 문장 | Instructions = system prompt |
| **손발** | 세계와 접촉하는 함수들 | Tools (W4) |
| **기억** | 대화·경험을 유지 | Memory (W10) |

대화는 **역할(role)** 이 붙은 메시지의 흐름이다: `system / user / assistant / tool`. 이 어휘가 학기 내내 코드와 논문에 그대로 나온다.

용어를 정확히: context window(한 번에 보는 최대 토큰)는 W9의 주인공이 된다.

# 자율성 — 정도의 문제다

**자율성(autonomy)** = 제어 흐름의 결정을 개발자가 아니라 LLM에 넘긴 정도.

정의상 자율성은 0/1 스위치가 아니라 **연속선**이다 — 에이전트냐 아니냐가 아니라 "얼마나 에이전트다운가":

| 자율성 | 예 | LLM이 정하는 것 |
|---|---|---|
| 고정 파이프라인 | 번역→요약→저장 | 없음 |
| 라우터 | 문의를 팀별로 분류 | 분기 1회 |
| 제한된 루프 | 통과할 때까지 코드 수정(≤5회) | 반복·중단 |
| 자율 에이전트 | "이 주제를 조사해줘" | 계획 전체 |

- 오른쪽으로 갈수록 유연하지만 **예측 어렵고 비싸다**
- 실무 원칙: **필요한 만큼만 오른쪽으로** — 이 원칙은 W15에서 정면으로 다시 만난다

# 스펙트럼의 왼쪽을 채우는 어휘 — 워크플로우 패턴

에이전트로 가기 전, 사람이 경로를 설계하는 **정형 패턴**들이 있다. 채용공고·기술문서에 그대로 나오는 표준 용어다:

| 패턴 | 한 줄 | 이 과목에서 |
|---|---|---|
| **Prompt chaining** | 출력을 다음 입력으로 직렬 연결 | W5 계획 |
| **Routing** | 입력을 분류해 다른 경로로 | W8 적응형 검색 |
| **Parallelization** | 병렬 호출 후 취합(투표) | W3 self-consistency |
| **Orchestrator–workers** | 중앙이 하위 작업 분배 | W11 멀티에이전트 |
| **Evaluator–optimizer** | 생성↔평가 반복 | W6 자기반성 |

16주 뒤 여러분은 이 표 전부를 **직접 구현한 상태**가 된다.

# 어떻게 생겼나 — 에이전트의 여러 형태

---

# 에이전트는 챗봇인가? — 아니다

**형태(form factor)** = 에이전트가 사람·시스템과 만나는 방식.

정의상 에이전트를 가르는 것은 제어 흐름의 소재이지 형태가 아니다 — 그래서 **같은 엔진이 네 형태로 온다:**

| 형태 | 예 | 상호작용 단위 |
|---|---|---|
| **대화형** (챗봇) | ChatGPT, 상담 봇 | 메시지 주고받기 |
| **위임형** (백그라운드) | Deep Research, 코딩 에이전트 | 과업 맡기고 결과물 검토 |
| **임베디드** | IDE 코파일럿, 편집기 보조 | 작업 현장 안에서 |
| **헤드리스** (부품) | 파이프라인·에이전트 속 에이전트 | API — 사람 없음 |

- 챗봇은 **첫 형태였을 뿐** — 무게중심은 위임형·임베디드로 이동 중
- 이 과목이 가르치는 것은 네 형태 공통의 **엔진**. 껍데기는 학기 끝에 씌운다

엔진은 어디에도 꽂힌다. W16에서 이 지도로 돌아온다.

# 언제 에이전트를 쓰나 — 판단의 감각

에이전트가 항상 답은 아니다. 대략의 기준:

**쓸 만한 자리** — 풀이 경로를 미리 코드로 못 박을 수 없고(열린 문제), 여러 도구를 거치는 다단계이며, 피드백으로 나아질 여지가 있을 때.

**쓰지 말 자리** — 절차가 고정돼 있거나(워크플로우가 더 싸고 안정적), 오류 허용도가 낮은데 검증 수단이 없거나, 단발 질의응답일 때.

> 판단의 핵심: 자율성은 **공짜가 아니다.** 유연성을 얻는 대신 예측가능성과 비용을 내준다.

# 이 과목은 무엇을 하나

---

# 16주의 한 문장

에이전트의 한계는 곧 학기 목차다:

1. LLM은 **행동할 수 없다** → 루프와 **도구** (W2·W4)
2. LLM은 **모른다·시효가 지났다** → 검색·**메모리** (W7–W10)
3. LLM은 **틀려도 끝** → 계획·**자기반성**·평가 (W5·W6·W13)

매주 **논문 2편으로 개념을 확인하고, 실습으로 그 부품을 직접 만든다.** 오늘 오후에는 그 첫 부품 — **모델을 부르는 두뇌 연결** — 을 세운다. (루프 자체는 다음 주에 직접 짠다.)

**오늘 발표:** 학생 발표는 다음 주부터. 오늘은 교수가 6장 템플릿으로 **Self-Consistency**(여러 번 생각하고 다수결)를 시연한다 — W3의 예고편이자, 여러분 발표의 모범.

# 요약

1. 챗봇과 에이전트의 차이는 모델이 아니라 **모델 주위의 구조**다
2. 에이전트의 정의 = **제어 흐름을 LLM이 결정하는가**. 자율성은 스펙트럼이다
3. 챗봇은 여러 **형태(form factor)** 중 하나일 뿐 — 엔진은 공통이고, 그 엔진이 이 과목의 내용이다

**다음 주 (W2. CoT → ReAct):**
"루프가 에이전트를 만든다"고 했다 — 그 루프의 **원전(ReAct)** 을 뜯어 읽고 직접 짠다. (첫 학생 발표: ReAct·CoT)
