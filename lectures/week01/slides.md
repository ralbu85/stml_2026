# 0–5′ · 왜 지금 에이전트인가

---

# 2022년의 AI vs 지금의 AI

**2022 — 챗봇:** 질문 → 답변. 끝.

**지금 — 일하는 AI:**
- **Deep Research** — 질문 하나에 수십 개 웹페이지를 *스스로 찾아 읽고* 보고서 작성
- **Claude Code** — 버그 리포트를 받아 코드를 *읽고, 고치고, 테스트 돌리고*, 실패하면 다시
- 항공권 예약, 실험 데이터 정리, 논문 서베이 …

**같은 종류의 언어모델인데, 무엇이 달라졌나?** ← 이 과목 전체의 질문

포인트: "모델이 좋아져서만이 아니다. 모델 *주변에 씌운 구조*가 생겼다."

# 차이는 모델이 아니라 **구조**다

<div style="display:flex; gap:2em;">
<div style="flex:1">

**챗봇**
```
질문 → [LLM] → 답변
```
- 1회 호출
- 아는 것만 말함
- 틀려도 그걸로 끝

</div>
<div style="flex:1">

**에이전트**
```
목표 → [LLM] → 행동 → 결과
         ↑___________|
        (될 때까지 반복)
```
- 여러 번 호출 (루프)
- 도구로 세상을 관찰·조작
- 결과를 보고 다음 수를 결정

</div>
</div>

이 **루프를 짜는 것**이 이번 학기 여러분이 할 일입니다.

# 5–15′ · 정의와 스펙트럼

---

# LLM 단독의 세 가지 한계

1. **지식이 멈춰 있다** — 학습 시점 이후를 모른다. 여러분 랩의 내부 문서는 영원히 모른다
2. **행동할 수 없다** — 계산기 하나 못 두드리고, 파일 하나 못 연다. 말만 한다
3. **한 번 말하고 끝** — 틀린 걸 스스로 확인하고 고칠 기회가 없다

→ 에이전트는 이 세 가지를 각각 **검색(W6–9) · 도구(W3) · 루프(오늘)** 로 푼다

<!--

# 에이전트 = LLM + 도구 + 루프

```
        ┌─────────────────────────────┐
        │  LLM (두뇌: 추론·결정)        │
        └──────┬──────────────▲───────┘
       행동 선택│              │관찰 결과
        ┌──────▼──────┐  ┌────┴───────┐
        │ 도구 (손발)   │→│ 환경/세계    │
        │ 검색·계산·API │  │ 문서·웹·OS  │
        └─────────────┘  └────────────┘
```

- LLM은 **텍스트로 행동을 선언**할 뿐 — 실제 실행은 우리가 짜는 코드(하네스)가 한다
- 이 그림의 모든 상자를 학기 중 직접 구현한다

---

# 판별 기준은 한 줄

> ## "LLM의 출력이 **다음에 무엇을 할지**를 결정하는가?"

- 개발자가 순서를 미리 다 정해놓음 → **워크플로우**
- LLM이 상황을 보고 순서·횟수·중단을 결정 → **에이전트**

<p class="small">Anthropic "Building effective agents"(2024)의 구분을 따름 — 업계 표준에 가까운 정의</p>

# 자율성 스펙트럼 — 이분법이 아니다

| 단계 | 예 | LLM이 결정하는 것 |
|---|---|---|
| 고정 파이프라인 | 번역→요약→저장 | 없음 (내용만 생성) |
| 라우터 | 문의를 A/B팀에 분류 | **분기 1회** |
| 제한된 루프 | 테스트 통과까지 코드 수정 (최대 5회) | **반복·중단** |
| 자율 에이전트 | "이 논문 서베이해줘" | **계획 전체** |

- 오른쪽으로 갈수록: 유연성 ↑ / 예측가능성 ↓ / 비용 ↓? **아니, 비용 ↑**
- 실무 원칙 (W15에서 다시): **필요한 만큼만 오른쪽으로**

# 15–25′ · 계보: 그냥 묻기 → CoT → ReAct

# 0단계: 그냥 물으면

```
Q: 345 × 687 = ?
A: 236,415        ← 그럴듯한 오답 (정답 237,015)
```

- LLM은 **다음 단어 예측기** — 곱셈 회로가 아니다
- 자릿수가 커지면 "정답처럼 생긴 숫자"를 만든다
- 지식 질문도 마찬가지: 모르면 **지어낸다** (환각)

"모델을 나무라지 마라. 원래 그런 물건이다. 우리가 할 일은 구조로 보완하는 것."

# 1단계: CoT — "풀이 과정을 쓰게 하라"

**Chain-of-Thought** (Wei et al., 2022) — 오늘 발표 논문 ②

> 프롬프트에 *풀이 과정이 달린 예시*를 넣으면, 모델도 풀이를 쓰며 답한다

| GSM8K (초등 수학 문제) | 정답률 |
|---|---|
| PaLM 540B, 그냥 묻기 | **17.9%** |
| PaLM 540B, **+ CoT** | **56.9%** (+39.0) |

같은 모델, 같은 가중치. **프롬프트만 바꿨는데** 3배.

# CoT는 왜 되는가 (직관)

- 사람도 삼자리 곱셈을 **암산으로 못 한다** — 종이에 중간 결과를 쓴다
- CoT = 모델에게 준 **연습장**: 중간 상태를 텍스트로 외부화
- 생성한 토큰은 다음 토큰의 입력이 된다 → **쓴 만큼 더 계산한 것**

> "생각을 더 시키면 더 좋아진다" — 이 직관이 다음 주(추론 모델) 전체의 씨앗

**그런데, CoT에겐 치명적 약점이 있다.**

---

# CoT의 약점: 눈감고 생각한다

```
Q: 2024년 노벨 물리학상 수상자의 소속 대학은?
Thought: 노벨 물리학상… 2024년은 아마 ○○○일 것이다.
         그는 △△대학 소속이므로… 답은 △△대학.   ← 전부 지어냄
```

- 추론 **구조**는 그럴듯한데, **사실**이 머릿속 기억뿐 → 환각 위에 쌓은 논리
- ReAct 논문의 진단: CoT 오류의 최대 원인이 바로 이 **환각**

**해법은? 생각 중간에 세상을 확인하게 하자.**

---

# 2단계: 반대쪽 극단 — 행동만 (Act-only)

```
Act 1: Search[아무거나 관련 단어]
Act 2: Search[또 검색]
Act 3: Finish[???]      ← 왜 검색했는지 잊음
```

- 검색은 하는데 **왜 하는지, 지금 어디까지 왔는지**를 말하지 않음
- 여러 단계 문제에서 목표를 잃는다

| HotpotQA (멀티홉 QA, EM) | |
|---|---|
| Act-only | **25.7** |
| 그냥 묻기 (Standard) | 28.7 |

행동만으로는 그냥 묻기보다도 **나쁘다**.

<p class="small">출처: ReAct 논문 Table 1 (PaLM-540B)</p>

# ReAct = Reason + Act (Yao et al., 2022)

**오늘 발표 논문 ①** — 생각과 행동을 **교차**시킨다

```
┌─→ Thought : 지금까지 안 것 정리, 다음 할 일 결정
│   Action  : 도구 호출 선언  Search[...]
│   Observ. : 도구가 돌려준 결과 (세상의 사실)
└───────────── 답이 나올 때까지 반복
```

- **Thought가 Action을 조준하고, Observation이 Thought를 접지(ground)** 한다
- 프롬프트 기법일 뿐 — 학습 없음, 예시 몇 개면 됨
- 오늘날 거의 모든 에이전트 루프의 원형

# 문제 (ReAct 논문 Figure 1, 요약 재구성)

> **Q.** Apple Remote 말고, Apple Remote가 *원래 제어하도록 설계된 프로그램*을
> 제어할 수 있는 다른 장치는?

풀려면: ① 그 프로그램이 뭔지 알아내고 → ② 그걸 제어하는 다른 장치를 찾아야 (**2홉**)

```
Thought 1: Apple Remote를 검색해서, 원래 어떤 프로그램을 위해
           설계됐는지부터 찾자.
Action 1:  Search[Apple Remote]
Observ. 1: Apple Remote는 2005년 Apple이 출시한 리모컨으로,
           Front Row 미디어 센터 프로그램 제어용으로 설계되었다…
```

**여기까지 모델이 한 일:** 문제를 쪼갰고(1홉째), 필요한 사실을 세상에서 얻었다

---

# 검색이 실패하면 — 추론이 경로를 수정한다

```
Thought 2: 원래 설계 대상은 Front Row다. 이제 Front Row를
           제어할 수 있는 다른 장치를 찾자.
Action 2:  Search[Front Row]
Observ. 2: 'Front Row'를 찾을 수 없음. 비슷한 항목:
           [Front Row Motorsports, Front Row (software), …]

Thought 3: 소프트웨어니까 Front Row (software)를 검색해야겠다.
Action 3:  Search[Front Row (software)]
Observ. 3: Front Row는 단종된 미디어 센터 소프트웨어로, Apple Remote
           또는 키보드 기능 키(function keys)로 제어할 수 있다…
```

**주목:** 검색 실패(Obs 2)가 죽은 길이 아니라 **다음 Thought의 재료**가 된다

<!--
[28분 지점] 이 슬라이드가 오늘의 심장. "Act-only였다면 여기서 무너진다 — 왜 실패했는지 말로 정리할 자리가 없으니까."
-->

---

# 답 — 그리고 방금 본 것

```
Thought 4: Front Row는 Apple Remote 또는 키보드 기능 키로
           제어된다. 답은 키보드 기능 키다.
Action 4:  Finish[keyboard function keys]   ✓ 정답
```

방금 본 것 세 가지:

1. **추론이 행동을 조준** — 무엇을 검색할지 Thought가 정했다
2. **관찰이 추론을 접지** — 지어내지 않고 검색 결과 위에서만 생각했다
3. **실패가 정보다** — "없음"이라는 관찰이 경로 수정을 만들었다

# 숫자로 확인 (ReAct 논문, PaLM-540B)

| 방법 | HotpotQA (EM) | Fever (Acc) |
|---|---|---|
| 그냥 묻기 | 28.7 | 57.1 |
| CoT (생각만) | 29.4 | 56.3 |
| Act (행동만) | 25.7 | 58.9 |
| **ReAct** | 27.4 | **60.9** |
| **CoT-SC → ReAct (결합)** | **34.2** | **64.6** |

- 의외로 HotpotQA에선 ReAct 단독 < CoT — **정직한 결과**. 내부 지식으로 충분한 문제도 있다
- 최고는 **결합**: 내부 지식(CoT)과 외부 확인(ReAct)을 상황 따라 — *어떻게 잘 섞나*가 곧 설계 문제
- 행동이 필수인 환경(ALFWorld)에선 압도적: **ReAct 71% vs Act 45%**

# ReAct의 한계 — 다음 주들의 예고편

- **한 발씩 greedy** — 잘못 든 길을 되돌아올 수 없다 → **W4 계획·탐색(ToT)**
- **틀려도 그대로 제출** — 자기 답을 의심하는 단계가 없다 → **W5 자기반성**
- **생각을 얼마나 시킬까** — 더 생각 = 더 비쌈 → **W2 추론 모델 (당장 다음 주)**

# 오후 실습: 이 루프를 직접 짠다 (`loop.py`)

```python
while steps < MAX_STEPS:
    reply = llm(history)              # ① Thought + Action 생성
    if is_final_answer(reply):        # ② 끝났으면 종료
        return extract_answer(reply)
    obs = run_action(reply)           # ③ 행동 실행 → 관찰   (오늘은 스텁)
    history += [reply, obs]           # ④ 관찰을 붙이고 반복
```

- 진짜 도구는 W3에서 — 오늘 `run_action`은 가짜(고정 응답)로 충분
