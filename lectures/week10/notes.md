# 10장. 메모리 (Memory)

사용자가 어제 알려 준 이름을 조수는 오늘 기억하지 못한다. 모델이 한 호출에서 읽는 컨텍스트는 세션이 끝나면 통째로 사라지고, 진행 중에도 오래된 이력은 요약·절단되어 복구되지 않기 때문이다(→ 9장). 세션을 넘어 정보를 지속시키려면 컨텍스트만으로는 부족하다. 이 장은 그 지속을 담당하는 자원, 메모리를 다룬다.

## 10.1 문제 — 컨텍스트는 메모리가 아니다

컨텍스트와 메모리는 다른 자원이다. **컨텍스트(context)** 는 이번 호출에서 모델이 읽는 입력이며, 호출이 끝나면 남지 않는다(→ 9.1). **메모리(memory)** 는 세션과 호출을 넘어 지속되는 외부 저장이며, 필요한 조각만 검색되어 컨텍스트로 들어온다. 컴퓨터의 비유로는 컨텍스트가 RAM, 메모리가 디스크에 해당한다. RAM은 빠르지만 용량이 작고 전원이 꺼지면 사라지며, 디스크는 느리지만 크고 지속된다.

메모리를 컨텍스트로 대신할 수 없는 이유가 이 대비에서 나온다. 지금까지의 모든 정보를 컨텍스트에 계속 쌓는 방식은 9장의 세 제약(상한·과금·위치 편향)에 그대로 걸린다. 대화가 길어지고 세션이 쌓이면 전부를 넣기는 물리적으로 불가능하고, 가능한 범위에서도 비싸며, 넣어도 중간의 정보는 잘 읽히지 않는다. 그러므로 지속 정보는 컨텍스트 밖에 저장하고, 매 순간 관련된 것만 골라 불러와야 한다.

이렇게 밖에 저장했다가 골라 불러오는 층이 **장기 메모리(long-term memory)**, 곧 세션을 넘어 지속되는 외부 저장이다. 이와 구분해 진행 중인 세션의 대화 버퍼는 **단기 메모리(short-term memory)** 이며, 9장의 컨텍스트 관리가 다룬 대상이다. 이 장은 장기 메모리를 다룬다. 장기 메모리의 저장·검색 골격은 6장 RAG와 같다. 외부 저장에서 관련 조각을 검색해 컨텍스트에 붙이는 구조가 그대로다(→ 6장). RAG에 없던 것은 둘이다. 무엇을 언제 컨텍스트로 불러올지를 에이전트가 스스로 결정하는 구조(10.2)와, 새 정보가 기존 사실과 충돌할 때 둘을 합치는 갱신(10.3)이다.

## 10.2 저장과 검색 — MemGPT

**MemGPT**(Packer et al., 2023)는 운영체제의 가상 메모리를 에이전트에 옮긴 설계다. 운영체제가 큰 가상 주소 공간을 작은 물리 RAM으로 다루기 위해 필요한 페이지만 디스크에서 올리고 내리듯, MemGPT는 큰 정보 집합을 작은 컨텍스트 윈도우로 다루기 위해 필요한 정보만 외부 저장에서 올리고 내린다. 계층은 두 층이다.

- **주 컨텍스트(main context)** — 윈도우 안에 상주하는 정보. 시스템 지시, 핵심 사용자 정보, 최근 대화. RAM에 해당한다.
- **외부 컨텍스트(external context)** — 윈도우 밖의 저장. 지난 대화 전체, 축적된 문서. 디스크에 해당한다.

10.1의 두 층으로 보면 주 컨텍스트는 단기 메모리가 상주하는 윈도우이고, 외부 컨텍스트는 장기 메모리의 저장소다.

> **[그림 10.1]** 두 층의 메모리 계층을 좌우로 배치한 그림. 왼쪽에 작은 상자로 주 컨텍스트(컨텍스트 윈도우, RAM), 오른쪽에 큰 저장소로 외부 컨텍스트(디스크). 두 상자를 잇는 양방향 화살표에 '페이지 인'(외부→주)과 '페이지 아웃'(주→외부)을 라벨로 달고, 그 이동을 지시하는 주체가 에이전트임을 화살표 위 도구 호출 아이콘으로 표시한다. 운영체제 가상 메모리와의 대응을 한눈에 보여 준다.

핵심은 이 둘 사이의 이동을 에이전트 자신이 결정한다는 것이다. MemGPT는 메모리를 읽고 쓰는 연산을 도구(→ 4장)로 모델에 준다. 컨텍스트에 없는 정보가 필요하면 모델이 외부 컨텍스트를 검색하는 도구를 호출해 관련 조각을 주 컨텍스트로 올리고(페이지 인), 주 컨텍스트가 가득 차면 오래된 내용을 외부로 내린다(페이지 아웃). 컨텍스트가 한계에 다다랐다는 신호도 모델에 전달되어, 무엇을 남기고 무엇을 내릴지 판단하게 한다.

페이지 인의 한 순간을 트레이스로 보인다. 주 컨텍스트에 없는 과거 정보를 사용자가 묻자, 모델이 스스로 검색 도구를 호출해 외부 컨텍스트에서 조각을 끌어 올린다.

```
[사용자]   지난달에 정한 발표 순서 그대로 갈까?
[모델]     (주 컨텍스트에 해당 정보 없음 → 외부 저장 검색)
           Action: recall_search("발표 순서 결정")
[코드]     외부 컨텍스트 검색 결과: "결정(지난달): 발표 순서는 ReAct, RAG, Reflexion 순 …"
[모델]     (결과를 주 컨텍스트로 올림 = 페이지 인)
           Final Answer: 네, ReAct, RAG, Reflexion 순서 그대로입니다.
```

이 트레이스는 읽기 방향(페이지 인) 하나만 보였지만, MemGPT의 도구 집합에는 오래된 내용을 밖으로 내리는 쓰기(페이지 아웃)도 있다. 6장의 에이전틱 RAG가 읽기, 곧 검색만 도구로 가졌던 것과 달리, MemGPT는 읽기와 쓰기를 모두 도구로 가져 모델이 자기 컨텍스트를 편집한다. 이 자기 편집이 MemGPT의 핵심이며, 페이징의 상세와 함수 설계는 발표에서 확인한다.

## 10.3 갱신 — Mem0

MemGPT가 저장과 반입의 구조를 세웠다면, 실제 운영에서 더 어려운 문제는 갱신이다. 새 정보를 덧붙이기만 하면 메모리는 모순으로 쌓인다. "나는 서울에 산다"를 저장한 뒤 몇 달 뒤 "부산으로 이사했다"가 들어오면, 둘을 모두 저장한 메모리는 검색 시 어느 쪽을 반환할지 알 수 없다.

**Mem0**(2025)는 이 갱신을 파이프라인으로 다루는 프로덕션 메모리 설계다. 새 정보가 들어오면 추출·조회·해소의 세 단계를 거친다.

1. **추출(extract)** — 대화에서 저장할 가치가 있는 사실을 모델에게 뽑게 한다. 인사말이나 잡담이 아니라 사용자의 선호·속성·결정 같은 지속 정보다.
2. **조회(retrieve)** — 추출한 사실과 관련된 기존 메모리를 검색한다. 갱신인지 신규인지 판정하려면 기존 상태를 먼저 봐야 한다.
3. **해소(reconcile)** — 새 사실과 기존 메모리의 관계를 판정해 갱신 연산을 정한다.
   - ADD: 관련 기존 메모리가 없으면 새로 추가한다.
   - UPDATE: 기존 사실을 보강·수정하면 갱신한다("서울" → "부산").
   - DELETE: 새 정보가 기존 사실을 무효화하면 삭제한다.

> **[그림 10.2]** 갱신 파이프라인을 왼쪽에서 오른쪽으로 흐르는 세 단계로 그린 그림. 대화에서 '추출' 상자로 사실이 나오고, '조회' 상자가 기존 메모리 저장소를 질의해 관련 사실을 끌어오며, '해소' 상자에서 ADD·UPDATE·DELETE 세 갈래로 분기해 각각 저장소에 다른 연산을 가한다. 새 사실을 무조건 덧붙이지 않고 기존 상태와 대조해 분기한다는 점을 분기 화살표로 보여 준다.

세 연산이 한 대화에서 어떻게 갈리는지를 예로 보인다. 왼쪽이 대화에서 추출한 새 사실, 오른쪽이 기존 메모리와 대조해 정해진 연산이다.

```
기존 메모리: (M1) 사용자는 서울에 산다.  (M2) 사용자는 채식을 한다.

"부산으로 이사했어."          → UPDATE M1: 서울 → 부산   (기존 사실의 변경)
"매운 음식을 좋아해."          → ADD  M3: 선호 = 매운 음식  (관련 기존 메모리 없음)
"이제 고기도 먹어."            → DELETE M2                 (기존 사실의 무효화)
```

모순 해소가 이 파이프라인의 어려운 부분이다. 두 진술이 정말 모순인지(거주지 변경), 둘 다 참인 별개 사실인지(집은 서울, 직장은 부산), 아니면 무관한지를 판정하는 일 자체가 판단을 요구하며, 이 판정을 모델에 맡긴다. 그래프 구조로 사실 간 관계를 저장하는 확장, 지연·확장성 분석은 발표에서 확인한다.

## 10.4 무엇을 기억하고 무엇을 잊는가

10.3의 갱신이 새 정보와 충돌하는 사실을 정리했다면, 낡거나 무관해진 사실을 정리하는 것은 다른 문제다. 저장 공간이 무한하지 않고 검색은 관련성으로 정렬되므로, 모든 것을 남기는 것은 답이 아니다. 무의미한 정보가 쌓이면 관련 검색의 정밀도가 떨어지고, 잘못 저장된 사실은 이후 검색마다 잡음으로 되살아난다(컨텍스트 오염이 세션을 넘어 지속되는 형태다, → 9.3). 그러므로 메모리에는 저장의 선별과 함께 **망각(forgetting)**, 곧 오래되거나 무관해진 항목을 능동적으로 제거하는 정책이 따른다. 갱신의 DELETE가 새 사실이 옛 사실을 무효화할 때의 삭제라면, 망각은 무효화가 아니라 가치가 낮아진 항목의 삭제다.

무엇을 반입하고 무엇을 잊을지는 같은 기준으로 정한다. 반입할 조각을 고르는 검색 점수를 세 성분으로 설계하고, 세 성분 모두에서 낮은 항목이 망각의 대상이 된다. 이 세 성분은 Generative Agents(Park et al., 2023)가 제안해 이후 널리 쓰인다.

- **관련성(relevance)** — 현재 질문과의 의미적 가까움. 질문과 항목의 임베딩 벡터 사이 코사인 유사도로 잰다(→ 6.2).
- **최신성(recency)** — 최근에 접근된 항목일수록 높은 점수. 시간에 따라 감쇠한다.
- **중요도(importance)** — 항목 자체의 지속 가치. 사용자의 핵심 속성은 잡담보다 중요하다.

검색 점수는 세 성분의 가중합(관련성 + α·최신성 + β·중요도)이며, 가중치 α·β는 정답이 미리 정해져 있지 않으므로 준비한 평가 셋으로 조정한다(→ 5.5). 세 성분의 대비가 컨텍스트 관리(9장)와의 경계를 분명히 한다. 9장의 선별이 이번 세션 안에서 관련성으로 골랐다면, 메모리의 검색은 최신성과 중요도를 더해 세션을 넘어 고른다.

## 10.5 정리

컨텍스트는 세션이 끝나면 사라지는 자원이고, 메모리는 세션을 넘어 지속되는 외부 저장이다. 단기 메모리는 진행 중인 세션의 컨텍스트 관리(9장)에 속하고, 장기 메모리는 세션을 넘는 외부 저장이다. 장기 메모리의 저장·검색 골격은 RAG와 같으며, 다른 것은 반입을 에이전트가 스스로 결정하는 구조(MemGPT)와 새 정보를 기존 상태와 대조해 추가·수정·삭제하는 갱신 파이프라인(Mem0)이다. 무엇을 남길지는 관련성·최신성·중요도로 검색하고, 무엇을 잊을지는 망각 정책으로 정한다.

이 장으로 from-scratch 단일 에이전트가 갖출 구성 요소가 모두 모였다. 에이전트의 네 구성 요소(Model·Instructions·Tools·Memory, → 1.3)가 실물로 채워졌고, 루프·검색·계획·반성·컨텍스트·메모리가 하나의 하네스에 얹혔다. 남은 방향은 이 단일 에이전트로 감당하기 어려운 규모의 문제다. 그 처방인 협업과, 손으로 짠 하네스를 프레임워크 위로 옮기는 전환을 11장이 다룬다.

**발표.** MemGPT(Packer et al., 2023) — 가상 메모리 비유의 계층 구조와 자기 편집(self-editing) 함수. Mem0(2025) — 추출·해소·갱신의 프로덕션 파이프라인과 모순 해소. 두 편 모두 무엇을 컨텍스트에 두고 무엇을 밖에 둘 것인가, 그 이동을 누가 결정하는가의 관점으로 듣는다.
